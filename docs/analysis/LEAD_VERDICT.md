## 零、一句话裁决

**定义确实太狭隘。但不是「窄一点」，而是「窄、假、半」三重问题叠加；而「一个有用的规律都找不到」有四层独立原因，其中两层是系统自己的缺陷（不是数据的问题）。**

同时必须承认一条反向事实：**即使把四层全部修好，也改变不了中奖期望**——但「修好后仍然找不到」和「现在找不到」的可信度完全不同，前者才是可信的「未检出」。

## 一、三重问题

### 1.1「窄」——7 条隐含窄化假设（P1 §2）

系统能表达的「规律」只有唯一一种句式：

```
f_θ : 历史 H_t → 候选号码集合 ⊂ {1..33}
检验：命中数 X_t = |f_θ(H_t) ∩ R_t|  vs  超几何基线 E = 6k_t/33
```

隐含窄化：① 必须是「选号函数」；② 必须是集合级可加统计量；③ 单变量/低维；④ 时不变单一效应；⑤ 必须覆盖全时间轴；⑥ 判据是「与均匀随机有差」——**越像随机越被判无效**；⑦ 只测红蓝命中数。

代价最高的两条：
- **`order`（开奖顺序）字段 0 处被读取**（P2 §2.2 全仓 grep 实证）——「先开出的球更容易再出现」这类假设在代码里根本不存在。P2 注入 position +35% 偏置，检出 **0/8**。
- **`sales`/`pool`（销量/奖池）从未使用**——这是系统手里唯一没碰过的第二数据轴。P1 新开 43 个统计量实测：BH 后 **0 显著**（但这是首次测，不是「测过没有」）。

### 1.2「假」——宣称 124 档，实际只跑 94 档（P1/P5/P6 + Lead 四方独立复现）

**这是本轮最重要的发现**：

```
V12 新增 8 个形态族的选择器用 history[-w:] 切片
  → asof_scan 传入的是 ScanContext（dict 子类，不支持切片）
  → KeyError: slice(-30, None, None)
  → discovery.py:1188  except Exception: chosen = set()   静默吞掉
  → k≡0 → exp≡0 → discovery.py:1303  if sd <= 0: continue  二次跳过
```

**全量枚举 124 个组合：OK 94 / FAIL 30。** 失败族精确为：
`sum_range` 6 + `span_range` 4 + `parity_cfg` 4 + `big_small_cfg` 4 + `route012_cfg` 4 + `ac_value` 4 + `consecutive_hot` 2 + `tail_group` 2 = 30。
**94 恰好等于 `discover()` 报的 `n_tested=94`**——所以「124 与 94 的差额」与最小历史长度无关，100% 来自此 bug。

两条**不同的**静默失败路径（必须分开看）：
| 路径 | 现象 | 危害 |
|---|---|---|
| A. `discover()` 快速筛选 | `sd<=0` → `continue`，**根本不进 `n_tested`** | 这 30 档从未参与搜索 |
| B. `rule_lifecycle.build_metrics()` | 返回 `delta=0.0, z=0.0, p_raw=1.0, n=3315` | **「从未检验」与「检验了无效应」完全不可区分** |

**讽刺之处**：这 8 个形态族正是 V11/V12 为响应用户「扩大规律的定义」而新增的东西。**用户要求扩大定义 → 系统加了 8 族 → 8 族从未真正运行 → 系统继续报「没有规律」。**

**测试为何没发现**：`tests/test_v12_shape_rules.py` 只测 `shape_rules` 模块本身，对 `asof_scan`/`discover`/`sum_range`/`ac_value` **零命中**（Lead grep 证实）。这是 858 全绿下的盲区。

### 1.3「半」——假设类对补集不封闭，系统自毁一半信号（P2 §4.2b，Lead 已核到源码行）

**核心恒等式**：对任意号码集合 S，`X_S + X_{S^c} ≡ 6`（每期开奖 6 个红球，必落在 S 或 S^c 中）。
⇒ **`delta_S + delta_{S^c} ≡ 0`**。即：**一个「显著为负」的过滤器，其补集就是「显著为正」的过滤器。**

而 `hypothesis.py:1441`：

```python
out["verdict"] = "支持" if delta > 0 else ("反对" if delta < 0 else "无显著差异")
```

`:1522-1524`：`反对 → status = "rejected"`。

**后果（P2 注入实测）**：给 6 个号各 ×1.10 的偏置后——
- `hot` 的 Δ 只有 **+0.027**（信号被稀释，且饱和：即使权重 ×3，λ 也只到 1.198）
- `cold` 的 Δ 达 **−0.054**（反向对齐，比 hot 灵敏 2 倍）
- 系统确实**看见了**信号，但看见的是 `cold` 的**负号**；负号被判 `rejected` 丢弃。

**所以：系统"看见一个坏掉的维度"，而不是"看见用户要找的那个规律"。** 这不是阈值松紧，是**假设类的一半被结构性丢弃**。

## 二、为什么「一个有用的规律」找不到——四层原因

| # | 原因 | 量化证据 | 性质 |
|---|---|---|---|
| **A** | **范畴错误**：单注 EV 由组合恒等式钉死 | `E[K]=12/11`、`Var(K)=729/968`，与选哪 6 个号无关；`ev_ratio_full≈0.45675` | 数学上不可能，非「未找到」 |
| **B** | **表示能力不足** | 94 个 filter 覆盖约 5e-5 候选空间；`order` 零读取；销量/奖池零使用 | 定义了但没测 |
| **C** | **状态机断崖** | `persistent` 需「最近段显著 ∧ 另有段显著」；`ERA_FAMILY_M=32` ⇒ H0 下 `P(persistent)≈3e-5`，真实 +3% 效应也只有 `≈3e-4`；`prereg_ok` 实际要 **z>4.3** | 判据过严 |
| **D** | **真 bug** | 30/124 从未运行（§1.2） | 工程缺陷 |

### 2.1 最有力的一条铁证：注入实验

用**真实** `discover`/`regime`/`rule_lifecycle` 代码，向数据注入「6 个号各 ×(1+r)」的号码偏置（这是"开奖机有偏差"的经典模型），每档 8 次重复：

| 注入强度 | quick BH 通过 | 阶段显著 | **persistent** | **usable** |
|---|---:|---:|---:|---:|
| H0（纯随机） | — | — | **0/8** | **0/8** |
| 6 号 +10%/号 | **8/8** | 6/8 | **0/8** | **0/8** |
| 6 号 +50%/号 | 6/6 | 6/6 | 3/6 | 3/6 |
| 6 号 +100%/号 | 6/6 | 6/6 | **6/6** | **6/6** |

**解读**：+10%/号的偏置**已经大得离谱**（真实彩票机若有此偏差，早被审计发现），系统第一层能 8/8 检出，但**走到 UI 上的 `usable` 是 0/8**。要 +100%/号 才能 6/6。

**⇒ 「找不到规律」的直接原因是判据链，不是数据。** 这一条彻底改写了前几轮的结论。

我另做的独立功效校准（Lead，每档 200 次）交叉印证：`Bonferroni(94)` 对 6 号偏置的检出率，+10% 仅 0.12、+15% 0.89、+20% 1.00 —— 即系统对「≥+15% 偏差」是有能力的，对「≤+5% 偏差」基本无能。

### 2.2 但必须同时说：修好之后仍然不会有「能提高中奖率的规律」

P5 做了反事实实验（内存适配层让 124 档真正运行）：最强候选 `sum_range{w30,[45,75)}` 达 z=+3.595 / p=0.000648 —— **比原来好 55 倍**，但 **BH=0.0804，仍在门槛之外**。

且它经追查是**恒等重述**，不是条件规律：该档候选集近似 {1,2,3,4,5,6}，候选号均值 7.58（理论 17.0），号码 1 在 63.7% 期次被选中；其依托的「小号偏热」在 33 窗口多重校正后 p=0.387、末 700 期 holdout 不复现(z=1.09)。

**总裁决（R-1）**：修 bug 是 P0，**但不得**在修完后把 `sum_range` 当「找到了」发布。理由只需一条就够：**BH=0.0804 > 0.05，它本来就没过校正门槛**。

**结论：不是模型不够强，是「设计不让它做」与「任务在 EV 上不可学」两件事同时成立，而「能力不足」在现有证据里无法被证实或证伪。**

| 提示词天花板 | 设计不让做 | `llm_lab.py:176` 的 `[:14000]` 截断把「统计检测力提示」整段切掉（ctx 实测 14579 字符）；`_params_ok` 参数必须逐字命中维度档位 |

## 五、产品侧为什么用户永远等不到「有规律」（P4）

同屏并存 **5 种判据不同**的「规律」含义，没有任何一次状态迁移能让它们同时变绿：

| 含义 | 当前结论 | 冲突 |
|---|---|---|
| ① 统计显著 | 0 条 | 主口径，永远 0 |
| ② 形态恒等约束 | 「可用」5 条 | **恒成立**，随机开奖也 100% 成立，却也叫"可用规律" |
| ③ 阶段有效性 | 0 条 | 已被否证，卡片仍在讲 |
| ④ 生命周期 | 未纳管 | 空转档位 |
| ⑤ LLM 洞察 | 0 条且**代码永久排除** | 按钮常亮，跑 1~8 分钟必不变 |

**「可用」这个词本身就是债务**：它同时意味「能被使用」(真) 与「有预测价值」(假)。
**已确认的现实违规**：`patterns_runtime.py:205` `counts["usable"] = _n_long + _n_phase`——**跨层求和**，是当前生产里唯一的此类违规。若 V12 也输出 L1+L2+L3 总数，首屏会变成「5 条可用，其中 0 条有预测力」，**比现在的「0 条」更误导**。

## 七、V12 方案（P6 收敛，Lead 已审）

**三层重新定义**：
- **L1 预测型** → 降级为**污染检测器**。不再以「找规律」为目标，但保留：这是全系统唯一「响了就一定是真事」的检测器（+15% 偏置检出率 0.89~0.93）。价值是「若开奖机被动手脚，这是唯一能发现的东西」。
- **L2 结构型** → **最大交付块**。组合恒等约束、奖级分布、方差比、覆盖效率、预算内最优组合。唯一真实数学收益：5 注从高重叠 `Ā=4.0` 改为互不相交，`P(≥1注≥4红)` 0.019517 → **0.024504**，达到/略超 iid 天花板 0.024265，**EV 恒 0.45673**。
- **L3 决策型** → 七项全部按「对/错/没做」分开计分。

**规模**：21 个任务、**22.5 人日**、真实 **2 路并行**、排期 **14 个工作日**。

**停止条件（量化）**：连续 3 批前置注册全无通过 → `LOTT_SEARCH_FROZEN`；最强候选 `min_p_adj>0.05` 且 `max|z|<3.49`(m=124) → 冻结搜索转 L2/L3。

## 十、诚实边界（全文生效）

1. **本系统不会、也做不到提高中奖概率。** 单注 EV 由组合恒等式钉死，与选号策略无关。
2. **「未检出」≠「不存在」。** 本数据能排除「≥+5.88% 号码偏置」级别的效应，**不能**排除更小的效应——那需要 5 万~40 万期数据。
3. **修复 bug 后的正确结论仍然是「未检出」**（BH=0.0804），只是这个「未检出」第一次变得可信。
4. **L2/L3 的全部交付都不改变 EV**，只改变分布、方差、形态合理性、决策可评分性。
5. 任何「提高命中率/中奖概率」的表述在本方案中**禁止出现**。
