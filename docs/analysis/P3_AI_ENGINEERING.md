## 0. 一句话结论

**「AI 作用不明显」的首要原因不是模型不够强，而是系统只允许 LLM 做三件「注定测不出东西」的事：按维度表复述（臂 B 实测 0/4 条是发现）、判断几乎恒为 hold 的衰减（哑判官一致率 99.19%）、在一条纯噪声序列上找一个经得起 BH 校正的规律（94 维全扫描最强候选校正后 p=0.162）。** 但代码审计同时证明：LLM 并**没有**被公平测过——它的输出空间被白名单映射器截断、它从未见过自己过去的假说与失败结果、评测口径在现有 N 下连「赢 60%」都要 388 期。所以正确的表述是：**「AI 没被允许发挥」与「任务本身在 EV 维度上不可学」两件事同时成立，而「模型能力不足」在现有证据里完全无法被证实或证伪。**

## 1. 五个质疑，逐条回击（证据优先）

### ① 提示词天花板：它真的只要求「系统已能测的形式」吗？

**先纠正一个事实**：`hypothesis.build_hypothesis_prompt` 已经**不在主链路上**。每期调度器
（`api_app._evolution_step():2235`）调的是 `hypothesis.mine_hypotheses`，后者用
`HYPOTHESIS_SYSTEM_PROMPT` + `build_hypothesis_prompt`；但那份 prompt 实测只有 **1264 字符**，
只喂「方法战绩 + 12 条统计候选 + 最近 12 期开奖」，且只允许 5 种动作
（`hypothesis.py:1034-1039`）。真正给 LLM 更多上下文的是 **`llm_lab`（维度工坊）**，
但它是**手动 API**（`api_app.py:2534 / 2721`），不进调度器。

| 位置 | 关键行 | 造成的天花板 |
|---|---|---|
| `hypothesis.py:1034` | `action.type 只能取以下五种之一（其它一律无效）` | 输出空间 = 5 种动作；prompt 正文里连 `prefer_structure` / `prefer_red_filter` 都没列（`ALLOWED_ACTION_TYPES` 有 8 种，docstring 写 6 种，**三处口径不一致**） |
| `hypothesis.py:1087` | `请**不要重复**这些，只补充新的` | 语义重复检测按 `spec_exp_id` 做，LLM 只要换措辞/换号码就能绕过 → 观测到的「新」不等于真新 |
| `llm_lab.py:56-66` | SYSTEM_PROMPT 第 2 条：`必须落到给定的维度表里…否则会被判为不可验证` | 维度表之外的想法**在提示词里就被宣判**为不可验证 |
| `llm_lab.py:176` | `body = json.dumps(ctx)[:14000]` | 上下文硬截断 14000 字符（实测 ctx=14579 字符）→ **「统计检测力提示」「可调用的维度族」「当前状态快照」整段被截掉**（`当前状态快照` 累计到 14071 字符处被切）。一份「教模型别过度自信」的提示，被截断掉了 |
| `llm_lab.py:325-332` | `_params_ok`：`params in fam["params"]` | 参数必须**逐字命中**维度表档位。说「近 25 期」而档位是 20/30 → 直接 `unmappable` |
| `llm_lab.py:126` | `discovery.discover(draws, top=12)` | 喂给 LLM 的「候选」只保留 top-12（按 \|z\|），结构性偏置（只喂最强的）|

**实证（真实调用，臂 A vs 臂 B）**：

* **臂 A（自由假设，不给维度表）**：LLM 返回 5 条，每条都带**完整的操作化定义 + 检验方法 + 效应量**（原文见 `exp3_llm_raw.json`），例如
  > 「对每一期 t，令 S_t=Σ r；统计样本均值 mean(S)…H0 μ0=6*(1+33)/2=102；σ0=6*((33²−1)/12)*(33−6)/(33−1)=459, σ0=21.4243；Z=(mean(S)−102)/(σ0/√3515)」
  这是**可以直接执行的统计方案**，质量不低于 LLM 在 `llm_claims.json` 里写的分析。
* 但按维度表口径判定：**5/5 全部 unverifiable**（`n_verifiable_now=0`）。原因不是它不可检验，而是
  「和值均值的全历史单点检验」不在 29 个维度族里。
* **臂 B（现有设计，给维度表）**：4 条全部可用（unmappable=0），但结论是 **3 条 noise + 1 条 regime_only，0 条 support**。
  也就是说：**在现有提示词下，LLM 的「可检验产出」全是复述维度表已有内容**（`exp3_armB.judged`）。

**结论**：`unmappable` 不是「LLM 提不出可检验的东西」，而是「验证器只认一种形状」。
**能力不足：否｜设计不让它做：是（决定性）｜任务不可学：仅对「每期可执行的选择器」成立。**

### ② 验证器天花板：会不会把「可证伪但形式不同」判死？

**会，而且是三重判定。**

1. **`_looks_unverifiable`（`hypothesis.py:933-939`）** 是**字符串包含匹配**，词表 15 条，含
   `"无法预测" / "不可预测" / "不存在规律" / "纯随机" / "无法优化"`。任何包含这些子串的陈述一律拒绝。
   风险不是措辞敏感，而是**误伤**：一句「若把 W 从 30 改成 25，该维度即无法预测下次命中」会被整条丢弃。
   **但当前没有数据能统计误伤率**：`data/llm_claims.json` 的 `runs[]` 只存 `{at, llm_used, n_claims, summary, overall, error}`，
   **没有 `rejected` 字段落盘**；`hypothesis._ask_llm` 把 `rejected` 返回给调用方，
   `api_app._evolution_step():2238` 只把 `llm_used / llm_count / llm_error` 写进内存 summary，**不入库**。
   → **实际拒绝率与拒绝理由分布：0 条可审计记录**。这是可观测性缺口，不是「拒绝率低」。
2. **`_reject_llm_hypothesis`（`:942-982`）** 要求 `evidence` 至少含 `n/lift/p_value/observed/baseline` 之一。
   这条对「全历史平稳性检验」型假说（臂 A 的 5 条都属此类）会直接判「无依据」——**而它们恰恰是可实现的**（见 §5，5/5 实现成功）。
3. **`llm_lab.evaluate_claim`（`:335-413`）** 才是真正的门：`_params_ok` 不过 → `unmappable`；
   `n<200` → `insufficient`；只有落在维度表档位且过 BH 的才算数。臂 B 的 4 条全部过了门，
   **说明「不可映射」不是 LLM 的输出问题，而是 prompt 已经把它的输出提前裁剪过**（见 ①）。

**「可证伪但形式不同」的实测反例**：臂 A 的 `h3/h4` 经我按 LLM 自己写的口径实现后，
**Bonferroni 下仍然显著**（p=0.0024 / 0.0071），却被现有验证器 100% 判为 `unverifiable`。
**能力不足：否｜设计不让它做：是｜任务不可学：否（这两个量是数据机制，见 §4）。**

### ③ 反馈闭环：LLM 见过自己过去假说的失败结果吗？

**没有。一次也没有。代码路径如下：**

```
api_app._evolution_step()                      # 每期调度器（api_app.py:2208）
  └─ hypothesis.mine_hypotheses({}, draws)     # :2235
       └─ hypothesis._ask_llm(report, stats, stat_hyps, draws)   # :1174
            └─ llm_client.chat_json(HYPOTHESIS_SYSTEM_PROMPT,
                   build_hypothesis_prompt(report, stats, stat_hypotheses, draws))  # :1116-1124
```
`build_hypothesis_prompt`（`:1044-1098`）的全部输入是：`report`（方法战绩）、`stats`、`stat_hypotheses`
（当轮统计挖掘）、`draws[-12:]`。**没有**：`hypothesis.load_registry()`、`data/llm_claims.json`、
`prereg_status`、`ability`、上一次的 `llm_rejected`。→ **同一份输入，每期得到「初次见到」的请求。**

同理，`llm_lab.ask_llm`（`:218-289`）三轮都在**同一次运行内**；`persist_run` 把结果写进
`llm_claims.json`，但 `build_lab_context`（`:116-170`）**不读**该文件。唯一能算「跨轮」的是
`hypothesis.evaluate_prereg`——可它判定的是**维度族**，而 LLM 的假说在 `register_prereg` 时的
`spec.family_key` 由 `_spec_canonical` 从动作里取；**`hypothesis.py:1044` 产出的 5 种动作中，
`boost_method / prefer_numbers / blue_prefer / blue_dedupe / blue_uniform` 都不携带维度 key**
→ 落到 `prereg_status="invalidated"`（`:1786-1790`）或压根不登记。

**硬证据（仓库现状）**：
* `data/hypotheses.json`：7 条，`source` 全部是 `stat`，`prereg_status` 全部 `null`，`status` 全部 `proposed`。**LLM 假说入库数 = 0。**
* `data/llm_claims.json`：`claims: []`（0 条），`runs` 4 条中 3 条 `llm_used=true, n_claims=0`。
  `overall` 是模型自己的长文分析（正确复述了 91 维、BH p=1.0、预期假阳性 4.55、MDE 0.22）——
  **模型的质量其实不差，是系统没让它的结论落地**：`register_llm_lab_claims` 只收 `support/reject/regime_only`，
  而 4 次运行里 `support=0`。
* `data/rule_lifecycle.json`：`judgements: []`、`skill: {}`、`llm_note: "AI 复核未启用（调用方关闭）"`
  （因为 `_evolution_step` 之后的 `run_cycle(use_llm=False)`，`api_app.py:2184`）。
  → **AI 复核技能分：一次都没跑过，不存在「AI 复核不准」的证据，只存在「AI 复核没开」的事实。**

**结论**：这是「**AI 根本没被允许学习**」，不是「AI 学不会」。**能力不足：无法判定｜设计不让它做：是（闭环缺失）｜任务不可学：不相关。**

### ⑤ 评测口径：现有统计量能检出「AI 有一点点用」吗？

`skill_stats`（`rule_lifecycle.py:793-820`）与 `llm_eval._pair_p` 的口径问题：

1. **基线选错（口径 + 计算）**：`_skill_note` 用 `lo <= baseline(0.5)` 判「不优于随机基线」，
   但一致率的正确基线不是 0.5，而是**哑判官**的准确率。实测 `decide_rule_state` 在 124 个维度上
   **123 个 hold / 1 个 demote**（`exp6`）→ **永远说 keep 的哑判官一致率 = 99.19%**。
   真实 AI 只要偶尔说 demote 而判断错一次，就会「低于随机基线」被降级。
2. **样本永远攒不够**：`skill_stats` 要 `n_action >= 10` 才下结论。每周 124 维度里平均 **0.0081×124 ≈ 1 条**动作为 action
   → 实测需 10 个周期才能攒到 10 条动作样本；而 **AI 复核根本没开**（§③），所以 `n=0`。
3. **Wilson 下界算「赢多少期才能证明」**（`exp1`，精确迭代）：
   （**精确 Wilson 下界 > 0.5 所需的最小 N**，按 k=round(p·N) 迭代求解；`exp1` 里的 `n_for_detect` 用的是
   正态近似 + Wilson 复核，给出 1565/388/170/93，**偏保守，不是这两个模型的功效计算口径**，这里以精确解为准）

   | 你真实的胜率 | 需要 N 期（精确 Wilson） | 在给定 N 时，一致率至少要达到多少才能让下界 >0.5 |
   |---|---|---|
   | 0.55 | **370** | N=60 → **63.3%**；N=180 → 57.8%；N=1000 → 53.1%；N=3515 → 51.7% |
   | 0.60 | **91** | 同上（N 越小，要求越高） |
   | 0.65 | 41 | |
   | 0.70 | 21 | |
   | 0.80 | 11 | |
   → **现有评测 N=60 期时，只有真实胜率 ≥63.3% 才能让 Wilson 下界超过 0.5**。而现实中的 AI 增量（若有）在 0.50–0.55 之间。**结论：现有口径在结构上无法检出「AI 有一点点用」，它只能证明「AI 一点用都没有」。**
4. **MDE（`exp1`）**：60 期 × 5 注 = 300 注时，红球命中 MDE = **0.1404 个/注**，蓝球命中 MDE = **0.0392**。
   而蓝球「模型有效」的合理量级是 0.0625−0.0625≈0.0075（LLM 自己的判断）→ 差 5 倍。
   即使跑满 3515 期 × 5 注（17575 注），红球 MDE 也还有 **0.0183**，蓝球 0.0051。

**结论**：评测口径不合格——**N 太小、基线太错、效应太小**。**能力不足：无法判定｜设计不让它做：是（评测设计）｜任务不可学：是（对可检出量级而言）。**

## 2. 「LLM 作为规律发现器」的能力边界表

| # | 维度 | 输入信息 | 输出空间 | 验证器 | 反馈 | 样本量 | 可检出效应量 | 实测结论 | 归因 |
|---|---|---|---|---|---|---|---|---|---|
| 1 | **假设生成（现有 `hypothesis` 通道）** | 1264 字符：方法战绩+12 条统计候选+最近 12 期（`build_hypothesis_prompt({}, {}, [], draws)` 实测；接上 `battle_report` 后仍只有约 3–5k 字符） | 5 种动作白名单 | `_looks_unverifiable` 字符串匹配 + 动作白名单 + evidence 字段 | **跨轮为 0** | n=1 次采样 | 未被测（无 LLM 假说入库） | 7 条库里假说全是 `stat`，`source=llm` 条数 **0** | **设计不让它做** |
| 2 | **假设生成（`llm_lab` 工坊）** | 14000 字符（实测 14579→截断），维度表+候选+分年 | 维度表档位内的 1~2 个 filter | `_params_ok` 逐字匹配 + `evaluate_claim` BH 门 | 仅本次运行内 3 轮 | n=1 | 0.0474 | 4 条全可用、0 条 support（真实调用） | **设计不让它做**（输出空间被裁剪） |

## 3. 为什么「首要原因不是模型不够强」

**论证链（每条都有代码行或实测数）**：

1. **模型看到了该看到的**：臂 A 的真实返回里，LLM 自己给出了正确的分布理论值（超几何方差 459、σ0=21.4243）、
   正确的检验形式（单侧 z、Bonferroni 33/16 的阈值）、甚至自己写了 `needs:"none"`。
   `llm_claims.json` 里它同样正确复述了「91 维、BH p=1.0、预期假阳性 4.55、MDE 0.22」。
   → **它的统计素养在现有任务上不是瓶颈。**
2. **它被系统挡在门外**：
   * 输出空间：5 种动作 / 维度表档位（`hypothesis.py:1034`、`llm_lab.py:325`）；
   * 输入被截断：`llm_lab.py:176` 的 14000 字符把「统计检测力提示」截掉；
   * 跨轮记忆：`build_hypothesis_prompt` / `build_lab_context` 都不读历史（§③）；
   * 复核未开：`api_app.py:2184` 的 `use_llm=False` 让 `judgements` 恒为空。
   → **「AI 作用不明显」的直接原因在系统侧，而不是模型侧。**
3. **即使模型完美，结果也不会变**：如果把 §4 的 5 条（全部可用、2 条显著）换成任意更强模型的输出，
   它们仍然无法进入出号链路——因为它们不是「每期可执行的选择器」，而在 **94 维全扫描的维度空间里，
   不存在任何 BH 显著的组合**（0/94，`exp2.A_scan`）。**能力再强也改变不了 0 个显著性。**
4. **唯一诚实的反证**：如果「AI 有增量」，那增量必然落在 **0.02–0.05 红球/期** 这个量级，
   而现有评测（N=60×5=300 注）的 MDE 是 **0.14**——**即使 AI 真有 0.05 的增量，评测也会判它「无用」**。
   所以「AI 作用不明显」的一部分其实是「评测看不见」。

**这个结论在什么条件下会被推翻**（必须同时满足 3 条）：
- **(a)** 出现一个**新维度/新检验**，在 **≥2 个互不重叠的时间段**独立达到 BH p<0.05（不是同一个窗口切片），
  且效应量 ≥ 0.05 红球/期（当前全空间最好 0.0474 且不显著）；
- **(b)** 用**真实 LLM 调用**（不是人工构造）在**修改后的输出空间**上产出该维度，并且可被确定性代码自动实例化
  （即改造方案 M1 落地后的实测）；
- **(c)** 在**外推期**（不是拟合期）上保持方向，且累计 n 满足 §4.5 的功效要求。
→ 只要 (a) 不成立，任何「换更强的模型」都不会改变结论。

## 4. 意外发现：LLM 臂 A 的两个「显著信号」是数据机制，不是规律

臂 A（自由假设）的 5 条假设，我按 LLM 自己写的 operationalization **全部实现并执行**（`exp4_impl.py`）：

| id | 假设 | 统计量 | raw p（单侧） | Bonferroni 后 |
|---|---|---|---|---|
| h1 | 红球 14 频率 > 6/33 | 694 vs 639.1 | 0.00917 | **0.303（不显著）** |
| h2 | 蓝球 1 频率 > 1/16 | 239 vs 219.7 | 0.0961 | 1.0 |
| h3 | 和值均值 < 102 | **100.981** vs 102 | **0.00239** | **0.00239 ✓** |
| h4 | 奇数个数均值 < 102/33 | **3.0444** vs 3.0909 | **0.00708** | **0.00708 ✓** |
| h5 | 相邻期和值负自相关 | r₁=−0.0032 | 0.425 | 不显著 |

**h3/h4 是真的吗？** 用 2000 条合成均匀序列做零分布（`exp5_sum_odd.py`）：

| | 真实值 | 合成零分布均值 | q2.5 | q97.5 | 经验 p（左尾） |
|---|---|---|---|---|---|
| 和值均值 | **100.981** | 101.993 | 101.325 | 102.688 | **0.003** |
| 奇数均值 | **3.0444** | 3.091 | 3.054 | 3.129 | **0.0065** |

分年检查：9 个阶段的均值在 97.9–102.9 之间游走，**线性趋势斜率 −0.141/阶段, p=0.537（无漂移）**。
→ 这是一个**常数平移**：全历史和值平均低 1.02 个点、每期少 0.047 个奇数。
机制解释（未在本轮独立验证，列为待办）：开奖前的号码集合生成或**数据录入/早期期号的完整性问题**，
常见于「前 N 期的红球不是标准 33 选 6」。**它不是可下注的规律**（对每期 EV 的影响 <0.05%），
但它是**真实存在的、可复现的数据事实**——而且**只有 LLM 主动去测「全历史矩」才会发现它**，
94 维扫描（每次都是「近 W 期热/冷/遗漏」）结构上不可能发现它。

**这恰恰是 P3 要回答的问题的答案**：LLM 能发现东西，但发现的是「数据层」的东西；
现有系统只会给它「选号层」的任务。

## 5. 真实 LLM 对照实验（一次，成本可控）

**设置**：2 次真实调用，`deepseek-v4-flash`（thinking 关闭），temperature 0.5，超时 90s。key 从 `.env` 读、不落地、不打印。

| 臂 | 输入 | 输出空间 | 返回 | 可检验率 | 发现数 |
|---|---|---|---|---|---|
| **A · 自由假设** | 数据摘要（频次/和值/最近 20 期），**不给维度表** | 自然语言 + 操作化 | 5 条 | 按维度表口径 **0/5**；按「可实现」口径 **5/5** | raw 3/5，Bonferroni **2/5** |
| **B · 维度表（现有设计）** | 29 族维度表 + 最近 12 期 | 维度档位 | 4 条 | **4/4** | **0/4** support（3 noise + 1 regime_only） |
| **C · 确定性扫描** | 3515 期 | 94 组合 | 12 条候选 | 100%（定义上） | BH 显著 **0/94** |

耗时：A=36.7s（触发一次「只返回 reasoning_content」重试），B=14.0s，C=11.9s。
成本：按 `llm_cost_log.jsonl` 实测单价 **7.2 元/百万 token**、历史 engine 调用均值 in≈4007 / out≈6912
推算，本实验 2 次调用约 **7 分钱**；一次完整 `llm_lab` 三轮约 **2–4 万 token，0.15–0.3 元**。

**读法**（必须同时读三列，不能只看中间）：
- 若只按现有验证器判 → 「LLM 产出可检验率 0% → AI 无用」。**这是错的**（§1②、§4）。
- 若按「可实现性」判 → 「LLM 产出可检验率 100%，还有 2 条显著」。**这也不足以说 AI 有用**：
  这 2 条是数据机制，不是选号规律。
- 真正的问题是：**LLM 的产出形状（全历史统计量）与系统的消费形状（每期选择器）不匹配**。

## 6. 三条可实施的改造方案（具体到文件+函数+输出空间+打分+判定周期+token）

> 全部方案**不复活** V10 删除项：不自由出号、不做 Kendall τ 排序、不做选择性推断、不做 CUSUM。
> 共同纪律：**LLM 只输出「结构化的新维度/新检验规格」，由确定性代码实例化并检验。LLM 从不产出号码、从不产出 p 值。**

### M1 · 维度提案器（LLM 提「新维度」，代码实现并检验）

| 项 | 内容 |
|---|---|
| **改哪个函数** | 新增 `lottery/dimension_proposer.py`：`build_proposer_prompt()` / `parse_proposals()` / `instantiate()`；**只读**调用方；提案落 `data/dimension_proposals.json`（新文件，不动 `data/hypotheses.json`） |
| **LLM 输出空间** | 严格 JSON Schema：`{name, target: red/blue, window_words:[…]或 expr, predicate:{op: in/not_in/top_quantile/between/…, args}, direction: up/down, rationale}`。**禁止**输出数字预测、绝对号码、p 值 |
| **代码如何打分** | `instantiate()` 把 proposal 编译成 `discovery.make_filter` 兼容的 selector（参数从 schema 白名单里取），然后：<br>① 语法可实例化 → `compiled`；② 跑 `discovery.asof_scan` 拿 obs 序列；③ `regime_of_filter` 做阶段画像；④ **新增族的 m 计入 `n_tested`** 后做 BH；⑤ 只有「≥2 个互不重叠阶段独立 BH<0.05」才 `support` |
| **N 期判定** | 每条提案注册后跑 **≥2 个不重叠阶段（≥600 期）**；累计 m 达到 `>=50` 才启用 Bonferroni。判据：`support` = 2 段都显著且方向一致；否则 `reject`。批次 ≥10 条才可判定（复用 R2 门槛） |
| **预期产出** | 每轮 5–8 条提案，其中可编译（`compiled`）率目标 ≥70%（当前臂 B 的 100% 是假象，因为它只复述已有维度；本方案的「新维度」才算数） |
| **token 成本** | prompt ≈ 2.5k（不给维度表全文，只给 29 个族名 + schema）→ out ≈ 1.2k/条 × 6 ≈ 7k ⇒ **单轮 ≈ 10k token ≈ 0.07 元**；每期 1 轮 ⇒ **年成本 <5 元** |
| **红线** | 提案必须经人工/代码审查后才进 `discovery.FAMILIES`；**永不进入出号链路，除非通过 M1 的判定** |

### M2 · 跨轮记忆（LLM 迭代：喂回它自己过去的失败）

| 项 | 内容 |
|---|---|
| **改哪个函数** | `hypothesis.build_hypothesis_prompt(...)` 增加 `history: Optional[list]` 参数；`_ask_llm` 从 `llm_lab.load_claims()` + `hypothesis.load_registry()` 读出「最近 20 条 LLM 假说及其 `verdict/verdict_zh/p_adjusted/n`」注入；同时把 `_parse_llm_hypotheses` 的 `rejected` 落盘到 `data/llm_claims.json` 的新 `rejections[]` 字段（**当前完全丢失，见 §1②**） |
| **LLM 输出空间** | 不变（仍是 5 种动作或维度档位），但新增一个**必填**字段：`why_not_tried_before`（引用历史条目的 id 或说明为什么上一轮的同类假说失败） |
| **代码如何打分** | ① 统计「重复率」= 本轮提案与历史提案的 `spec_exp_id` 碰撞率（目标 <20%）；② 统计「引用准确率」= `why_not_tried_before` 提到的历史条目是否真实存在且判决正确（**纯确定性校验，0 误差**）；③ 对比注入前后 3 轮的 `support` 率 |
| **N 期判定** | 12 次运行（约 12 期）后比较 A/B：有记忆 vs 无记忆的「可编译率」与「重复率」。判据：重复率下降 ≥50% 且引用准确率 ≥90% |
| **token 成本** | prompt +1.5k（20 条历史摘要）⇒ **单轮 ≈12k token ≈ 0.09 元**，每 3 期跑 1 次 ⇒ **年成本 <20 元** |
| **为什么这是纯收益** | 它不改变模型能力，只改变「它是否知道上次错了」。当前证据（§③）显示它**完全不知道**——这是零成本可修的系统缺陷 |

### M3 · 数据异常期检测器（LLM 挑「可疑数据点」，代码检验）

| 项 | 内容 |
|---|---|
| **改哪个函数** | 新增 `lottery/data_audit.py`：`build_audit_prompt()` / `parse_anomalies()`；**复用** §4 已证实的 h3/h4 作为**已确认的基线异常**（和值均值偏 −1.02、奇数偏 −0.047） |
| **LLM 输出空间** | `{issue_range:[start,end], feature:"sum/odd/span/zone/frequency", observed_vs_expected, suspicion:high/medium/low}` —— **只许指名期号区间与特征，不许给结论性 p 值** |
| **代码如何打分** | 对每个候选区间，用**确定性代码**算：① 该区间的 χ²/t 统计量 vs 全历史；② 与合成均匀序列的零分布对比（`exp5` 同款）；③ 「该区间是否落在已知数据来源切换点附近」（`db.draws.source` 字段）；判定：`real_defect` / `regime_shift` / `noise`。**LLM 的报错率 = 它指名的区间被判定为 noise 的比例** |
| **N 期判定** | 每个季度（约 40 期）跑一次；**判据：`real_defect` 命中率 ≥1 个/季度**（即它确实找得到 §4 那类问题），且 `noise` 占比 <80% |
| **token 成本** | prompt = 分年统计表（≈3k）+ 检测器输出（≈2k）⇒ **单次 ≈6k token ≈ 0.04 元**，每季 1 次 ⇒ **可忽略** |
| **为什么它能做好** | 找「某段数据不像均匀抽样」比「找一条能下注的规律」容易一个数量级：样本是全历史、检验是单点、不需要每期可执行。**§4 已经证明 LLM 在同类任务上有产出。** |
| **额外收益** | 这类检测能直接回答用户「为什么和值老是偏低」的疑问，且**不承诺中奖率**——它属于「数据质量」，不是「预测」 |

## 7. 「AI 到底该放在哪」：岗位打分
