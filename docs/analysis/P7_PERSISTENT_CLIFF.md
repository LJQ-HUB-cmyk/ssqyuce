## 0. 一句话结论

**C —— 不必做。** 不是「优先级低」，是**做了会让系统变差**。

三条互相独立的决定性证据（任一单独成立就足以否掉）：

| # | 证据 | 数字 |
|---|---|---|
| **①** | 新档在**纯随机**数据上会让首屏出现「可用」 | H0 下 8 次重复有 **2 次**命中（25%），而现状 `persistent` 是 **0/8** |
| **②** | 新档在**真实数据**上唯一的产出，恰好是刚修完 bug 的那个族 | `sum_range{w:30,lo:45,hi:75}`，`p_bonf(m=124)=0.0464`，而权威口径 BH=**0.0804 > 0.05** |
| **③** | 把「每次运行的误报率」换算成「用户一年内看到假规律的概率」 | 现状 **5.3%** → 新档 **99.95%**（20 倍级恶化） |

检出率的账同样是负的：新档在真实 3515 期上新增 usable = **+1 条，且那一条是假的**（§6.2）。

**现在应该把力气放到 L2/L3，而不是继续调 L1 判据。**

## 1. 断崖到底卡在哪一步：四道门的逐门衰减表

### 1.1 四道门的真实代码

`lottery/patterns_runtime.py:128-133`：

```python
_long_term_ok = (
    (status in USABLE_STATUSES)           # 门1  G1：regime.status ∈ ("persistent",)
    and h.get("status") == "validated"    # 门2  G2：A/B 实战回放判「支持」
    and h.get("prereg_ok") is True        # 门3  G3：前置注册（累计口径 Bonferroni）
    and _src != "llm"                     # 门4  G4：来源非 LLM

```

> **必须先把上游说清楚**：`build_snapshot` 里 `discovery` 扫描出的条目 `usable` **恒为 False**
> （`tier_of_scan` 只给 monitor/rejected，`patterns_runtime.py:180-200`）。能进 `usable` 的只有**假说库条目**。
> 所以「断崖」的上游喂料只有 `discover(top=12)` 的 **12 条候选**。这不是本文的假设，是代码事实——
> 它直接决定了后面所有门的上限：**12 条喂料里没有信号，下游再宽松也是 0。**

### 1.2 逐门衰减表（真实代码，`gates_funnel.py`）

### 1.3 解读（三条，都对决策有直接影响）

1. **第一道掉到 0 的门是 G1（`status=="persistent"`），在 H0 与 +10% 全部为 0。**
2. **G2 不是瓶颈，G3 才是第二道墙**：`+50%` 时 12 条里有 **7 条**通过了 G2（`validated`），
   但**一条都没过 G3**——因为 `evaluate_prereg` 的累计口径把 α 压到 `0.05/m_cum`，量级与 G1 的 `0.05/32` 相同。
   ⇒ **只掀 G1 一道门，等于把瓶颈原样挪到 G3，usable 仍然 ≈0。** 这不是推测，是上表实测。
3. **G4（source!=llm）在 scan 通道恒过**，不是瓶颈，无讨论价值。

> **一句话**：断崖不是「一道门太严」，而是**三道 α≈2e-3 的门串联 + 上游只有 12 个候选**。
> 联合通过率 ≈ `P(G1)·P(G2)·P(G3)`，任何单独一道放宽 5 倍，联合仍被另两道锁死。

## 2. `persistent` 是否「过严」？`ERA_FAMILY_M=32` 是口径错还是有意保守？

### 2.1 先纠一个我自己的量纲错误（Lead 指出，已独立复算确认）

v1 版本把「单号 150 期累计 sd」与「6 号集合的均值标准误」混用（`sd_hit=4.339` 又再除 `√n`），
导致 z 被放大 ~5 倍、MDE 被算成 +63.7%。**正确口径（全部统一到「单期配对差」尺度）**：

```
var1 = k·p·(1−p)·(N−K)/(N−1) = 0.753099          # 单期命中数方差，k=6
sd1  = 0.867812868                                # 与 discovery.SD_HITS 逐位一致
se   = sd1/√n_era                                 # n=150 → 0.070863
mu   = MEAN_HITS·r = 1.0909·r                     # 每期增量
MDE  = (z_{α/2·m} + z_{0.8})·se / 1.0909          # 换算成「相对提升」
```

### 2.2 单阶段 MDE（修正后）

| 口径 | 单阶段 α | z 临界 | **单阶段 80% 功效所需相对提升** |
|---|---:|---:|---:|
| `locked`, **M=32（现状）** | 1.5625e-3 | 3.1628 | **+26.0%**（Δ=0.2837 红球/期） |
| `locked`, M=24（当前实测段数） | 2.0833e-3 | 3.0781 | **+25.5%**（Δ=0.2777） |
| 不校正（raw α=0.05） | 0.05 | 1.9600 | **+18.2%**（Δ=0.1985） |

**关键读数**：分母 32→24 只把 MDE 从 **+26.0% 降到 +25.5%（≈0.5pp）**；
即使**完全不校正**也只到 +18.2%。而用户语境的有效应在 **+3%~+15%**，
而真实数据最强候选的长期效应只有 **+5.0% 相对提升（+0.0542 红球/期，§6.1）**——**差 5.2 倍**。

⇒ **「调 `ERA_FAMILY_M`」或「换 BH」是无效改动**：它连 MDE 的一个零头都动不了，
更不可能把 +3%~+15% 变成可检出。**这个结论比 v1 估的 +63.7% 更硬**（v1 的 63.7% 会让人误以为
「只要把分母降到 24 就能改善一点点」，实际是「连 0.5pp 都不到」）。

### 2.3 单阶段在不同效应下的显著概率（修正后，locked M=32，n=150）

| 相对提升 | z 偏移 | P(单阶段显著) locked M=32 | M=24 | 不校正 |
|---:|---:|---:|---:|---:|
| +3% | 0.46 | 0.36% | 0.42% | 5.4% |
| +10% | 1.54 | **5.2%** | 6.0% | 9.6% |
| +15% | 2.31 | **19.7%** | 21.4% | 19.7% |
| +26%（MDE） | 4.00 | 52.0% | 55.7% | 64.3% |
| +30% | 4.62 | 77.9% | 80.6% | 77.9%→**84.2%** |
| +50% | 7.70 | ≈100% | ≈100% | ≈100% |

> **这张表是「调 α 无效」的最直观证据**：+10% 时单阶段显著概率只有 **5.2%（M=32）/ 6.0%（M=24）**
> ——**分母从 32 降到 24 只涨了 0.8 个百分点**。即使完全不校正（α=0.05）也只有 9.6%。
> 检验力不在这里，`locked` 只是把已经很小的数再乘 0.8。

### 2.4 状态机顺序是不是瓶颈？（真实 `regime_status`，6000 次 MC/格，修正后）

| 场景 | 口径 | P(persistent) | 状态分布（主要） |
|---|---|---:|---|
| H0 | locked M=32 | **0.0000**（0/6000） | noise 96.5% / stale 3.1% |
| H0 | locked M=24 | **0.0000** | noise 94.8% / stale 4.5% |
| H0 | bh（动态分母） | **1.7e-4** | noise 95.2% / persistent 0.02% |
| 全 24 段各 +10% | locked M=32 | **0.0098** | stale 60% / noise 28% / fading 11% / **persistent 1.0%** |
| 全 24 段各 +15% | locked M=32 | **0.0567** | stale 62% / fading 32% / **persistent 5.7%** |
| 全 24 段各 +30% | locked M=32 | **0.451** | fading 54% / **persistent 45.1%** |
| 全 24 段各 +50% | locked M=32 | **0.973** | **persistent 97.3%** |

**这张表回答了两个问题**：

1. **状态机的判定顺序（flipped→emerging→persistent）没有吃掉检出力。**
   当效应在**所有段上一致存在**时，`persistent` 的检出率随效应急剧上升（+50% → 97%）。
   它只在「仅最近一段显著」时判 `emerging`——这是**有意**的（单段显著本就是搜索出来的假阳性）。
2. **瓶颈是「150 期单阶段 × 锁定 α」这个物理极限，不是判据写法。**
   `persistent` 在 +10% 只有 1.0%、+15% 只有 5.7%，而 MDE 是 **+26%**。
   ⇒ **要在 +10%~+15% 上有检出力，必须改「阶段长度」（150→600 可把 MDE 降到 +13%）或「不用阶段」——
   这两个都不在 `persistent` 判据里。** 所以「做 persistent 新档」从设计上就打不到问题所在。

> ⚠️ 与 P2 实测的对照：P2 实测「+10%/号 → persistent 0/8、+50%/号 → 3/6」。
> 本文 MC 的 97%(+50%) 是**完美捕获上界**（假设 filter 完整吃到偏置）；P2 的真实注入因
> **通道稀释**（`hot` 饱和、信号主要落在反向 `cold`）只能拿到 3/6。
> **两者不矛盾：MC 是上界，P2 是实测。** 本文结论只用「上界都不够」这一点，不依赖具体值。

### 2.5 `ERA_FAMILY_M=32` 是口径错吗？——不是

`regime.py:124-139` 注释明确：固定分母换来「**历史段 p_adj 永久不变**」。若改成「当前段数」，
加一期导致段数变化就会让历史段 p 值集体漂移——那正是 V10-07 花一个版本修掉的不可复现性。
**改它不是修 bug，是撤销一个显式设计决定，且收益已被 §2.2 量化为 ≤0.5pp MDE / 真实数据 0 条新增。**
⇒ **建议不动**（与 P2 §7.2-N2、Lead N2 一致；本文补上量化）。

## 3. 如果做 `persistent_effect` 新档：候选设计与 H0 校准

### 3.1 候选设计（全部只用现有字段，不引入新统计量）

| 代号 | 定义 | 多重性 / scope |
|---|---|---|
| **L0 现状** | `regime.status == "persistent"` | 阶段 α=0.05/32；scope=12 候选×24 段 |
| **N1** | 全量 3315 期配对差 t 检验，**BH（m=12，即本次 scan 的候选数）** <0.05 且方向 + | m=12；scope=12 候选×全量窗口 |
| **N1b** | 同 N1，但 **Bonferroni(m=124)**（= 声明空间总数，固定分母） | m=124；scope=124 |
| **N2** | N1 ∧ **最近 3 段 delta 全为正**（方向一致，不要求各段显著）= **P2 §7.1-S2 原建议** | 同 N1 |
| **N3** | N1 ∧ 最近 5 段 delta 全为正 | 同 N1 |
| **N4** | 只要求 `recent.p_adjusted<0.05` 且 delta>0（最激进松口，作误报率参照） | 分母 33 |

### 3.2 H0 校准 = 决定性指标（`persistent_effect_calib.py`，每次跑完整 `discover(top=12)` 全 124 档）

**每次「运行」= 一次真实扫描 → 12 条候选 → 逐方案判定；「有命中」= 该次运行里至少 1 条通过该方案。**
这正是「用户某一期登录，首屏会不会出现一条假『可用』」的口径。

| 方案 | **H0 纯随机**（n=8） | **+10%/号**（n=8） | **+15%/号**（n=8） | +30%/号（n=2） | 读数 |
|---|---|---|---|---|---|
| **L0 现状 `persistent`** | **0/8（0%）** | 0/8 | 0/8 | 0/2 | 不误报，但也不检出 |
| **N1 长期显著（BH m=12）** | **2/8（25%）** | **8/8** | **8/8** | 2/2 | H0 侧 25% 不可接受 |
| **N1b 长期显著（Bonferroni m=124）** | **0/8（0%）** | 3/8（37.5%） | **8/8（100%）** | 2/2 | 唯一 H0=0 的变体，但 n=8 无法证明 ≤5% |
| **N2 = N1 ∧ 近 3 段同向** | **2/8（25%）** | **8/8** | **8/8** | 2/2 | 与 N1 同样误报——**「方向一致」并不降误报** |
| **N3 = N1 ∧ 近 5 段同向** | 2/8（25%） | 7/8（87.5%） | **8/8** | 2/2 | 同上 |
| **N4 仅近窗显著** | 0/8（0%） | 0/8 | 0/8 | 1/2 | 分母 33 太严，等于没改 |

> **N1b 值得单独一看**：它在 H0 是 0/8、+10% 是 3/8、+15% 是 8/8——
> **如果把「长期显著」的校正口径从 BH(m=12) 换成 Bonferroni(m=124)（即用声明空间做固定分母），
> 这个新档在 H0 侧确实干净。** 这是本文唯一被数据支持的温和变体。
> 但它的 H0 证据只有 **0/8**（Wilson 上界 0.32），**不足以通过 §5.1 要求的「n≥40 且上界 ≤5%」**；
> 且它在真实数据上仍然只能放出 `sum_range` 那一条（p_bonf=0.046 < 0.05，但权威 BH=0.0804）。
> ⇒ **它是「值得做一次正式校准」的候选，不是「现在就该做」的候选**（见 §7.1 结尾）。

**逐次明细（每次运行的命中条数，H0 与 +10% 并排）**：

| 重复 | H0 · N1 | H0 · N2 | +10% · N1 | +10% · N2 | +15% · N1 | +15% · N2 |
|---|---:|---:|---:|---:|---:|---:|
| 0 | 0 | 0 | 7 | 2 | 11 | 3 |
| 1 | 0 | 0 | 5 | 1 | 12 | 10 |
| 2 | 0 | 0 | 3 | 1 | 10 | 3 |
| 3 | **3** | **1** | 3 | 2 | 12 | 6 |
| 4 | 0 | 0 | 9 | 4 | 12 | 4 |
| 5 | 0 | 0 | 11 | 5 | 12 | 4 |
| 6 | **7** | **7** | 9 | 3 | 10 | 4 |
| 7 | 0 | 0 | 2 | 2 | 9 | 3 |

> **同一行左右对照是最有力的读法**：+10%/+15% 每一行的命中条数（3~12）
> 与 H0 异常样本（第 3、6 行：3、7 条）**在数值上完全重叠**。
> 也就是说，**一个用户在 H0 数据上看到 3 条「可用」，与在真实 +10% 偏置下看到 3 条「可用」，
> 系统是分不出来的**——这正是「首屏假规律」的精确形态。

### 3.3 三条必须说清的统计诚实

**(a) 「+10% 8/8 vs H0 2/8」不足以证明新档可用，但足以否掉它。**
n=8 时 H0 的 Wilson 95% 上界约 0.55，与 +10% 的 0.68 重叠——**所以本文不用它来「证明检出」**。
但决策只需要**上界**：H0 的**点估计已是 25%**，Wilson 下界 0.07，**远高于可接受的 5%**。
一个「最乐观也要 7%、点估计 25%」的新档，不该进生产。**这是 C 的理由，不是 A 的理由。**

**(b) N2「方向一致」**不**降低误报（在 n=8 下无法证明它降误报）。**
P2 §7.1-S2 曾预期「长期显著 + 近 K 段方向一致」能保持 FWER≤0.05。
**实测不支持**：H0 下 N2 与 N1 的「运行级命中」完全相同（2/8 vs 2/8；H0-6 里 7 条同时满足 N2），
N3（近 5 段）也是 2/8。**诚实说明**：N2 的唯一差别在**条数**（H0-3：N1 3 条 → N2 1 条；H0-6：7 → 7），
所以「N2 一点没用」说过头了；准确表述是：**在运行级口径上，N2 没有把误报率从 25% 降下来**。
原因：这些过滤器的段间 delta **强正相关**（同一批 draws、重叠的号码集合），
「3 段同向」几乎不提供独立信息 ⇒ **加了一个不降误报、只降检出（+10%: 8/8→8/8，+15%: 3/3→3/3，但条数 6.12→2.50）
的约束，代价明确大于收益**。

**(c) N1 的 H0 率高于名义 5%，机制已定位。**
名义上 BH(m=12) 在 H0 下 P(≥1)=4.96%（10 万次 MC，`h0_hb_vs_bonf.py`），但实测 25%。
两个来源：
1. **12 条候选高度相关**（重叠集合、同批 draws），BH 的 step-up 在强正相关下会低估族错误率；
2. **资格重选（selection-on-window）**：`hot/cold/omission_*` 等的选择集合由「最近 W 期」动态决定，
   于是同一期的入选与前期波动相关，逐期配对差不独立，`ttest_1samp` 的 H0 分布偏离名义 t。
   **本文对 (2) 做了对照实验但未能证实其为主因**（见 §6.3「未确认」），
   **所以这里只声称「实测率高于名义」，不声称「机制已完全解释」。**

## 4. 反方向论证：做了会不会反而更糟？（量化「假规律的代价」）

### 4.1 首屏语义：从「0 条」变成「N 条不可靠」

用户此前六轮的病根是「频繁给空结果/假结果」。V12-04 刚把跨层求和拆掉，理由正是
「5 条可用其中 0 条有预测力，比 0 条更误导」。**新档做的正是同一件事**：把 `usable` 从
「阶段持续 + A/B + 前置注册」放宽为「长期显著」，而长期窗口恰恰是**最容易被 3515 期噪声命中**的窗口
（MDE +5.9%，见 V12_ACCEPTANCE；而真实数据最强候选 +5.0%）——
**它在「刚好够不着」的位置上，会把 5% 的假阳性直接变成首屏的「可用」。**

### 4.2 量化：一次运行的误报率 → 用户一年内看到假规律的概率

每期一次快照、一年约 150 期（3515 期/23.4 年）。按上表 H0 率换算：

| 方案 | 每期运行误报率 | **一年内至少出现一次假「可用」** | 期望假规律条数/年 |
|---|---:|---:|---:|
| **L0 现状 `persistent`** | 3.6e-4（P2 实测 3e-5/候选×12） | **5.3%** | 0.05 |
| **N1 长期显著（BH m=12）** | 4.96e-2（名义）/ 0.25（实测） | **99.95% / 100%** | 7.4 / 37.5 |
| **N1b（Bonferroni m=124）** | 名义 4.86e-2 / **实测 0/8** | 名义 **99.94%** / 实测不可估（Wilson 上界 32%） | 名义 7.3 |
| **N2（N1 ∧ 近 3 段同向）** | 4.96e-2 / 0.25 | **99.95% / 100%** | 7.4 / 37.5 |
| **N4 仅近窗显著** | ~0（分母 33） | ~0 | 0 |

> **口径说明**：「名义」= 假设 12 个候选独立时的解析值（10 万次 MC 已核实）；
> 「实测」= 真实 `discover(top=12)` 链路上的观测（n=8）。
> 两者对 N1/N2 相差 5 倍（5% vs 25%），差距来自候选间相关与 §6.3(3) 未确认的机制，
> **所以年化换算一律用实测值**。N1b 的实测是 0/8，**无法据此认证它安全**（Wilson 上界仍 32%）。
>
> **这是本文最重要的一张表。** 「每期 5%」听起来可控，但**系统是每期都跑的**：
> 一年 150 次 × 5% ⇒ **假规律是近乎必然事件**。现状 5.3%/年 与 新档 99.9%/年
> 差的是**「基本不会」vs「几乎一定」**。这正是用户抱怨的那个现象。

### 4.3 与「禁止邀功」纪律的直接冲突

R-1 裁决原文：「修 bug 是 P0，**但不得**在修完后把 `sum_range` 当『找到了』发布。
理由只需一条：**BH=0.0804 > 0.05**」。

新档在**真实数据**上唯一的产出，恰恰就是 `sum_range`（§6.2）。**做这个新档 =
绕开 R-1 的禁令，把那个被明确禁止发布的东西换个字段名发出去。** 这是纪律层面的硬冲突。

### 4.4 与 V12-04 的冲突

V12-04 把 `counts.usable` 收紧为「= `usable_long_term`，禁止跨层相加」。
新档会**在 `usable_long_term` 这一层里混入两种证据强度不同的东西**（阶段持续 vs 仅长期显著），
等于在刚拆掉跨层求和的同一层里重新做一次「语义混合」。**要么再加一层（复杂度），要么污染这一层（误导）。**

| # | 方案 | 预期效果（实测/量化） | 风险 | 工作量 |
|---|---|---|---|---|
| **A** | **做 `persistent_effect` 新档**（N1/N2） | 真实数据 **+1 条**（且是 p=0.046 的 `sum_range`）；+10% 检出 8/8 | **H0 误报 2/8；一年 99.9% 出现假规律；违反 R-1** | 3~4 人日（状态机+快照+前端+测试） |

| **C** | 只放宽 `prereg`（G3） | G3 是第二道墙；放开它 ±1 道门仍在（G1=0）⇒ 真实数据 **+0 条** | 破坏 R1/R6「累计口径」，前置注册失去意义 | 1~2 人日，**收益≈0** |

**E 是唯一有真实、可验证收益的方向**（L2 的 0.0245 是精确枚举的恒等式，不是统计推断）。

### 5.1 如果一定要动 L1，唯一可接受的方向（但不建议现在做）

若未来某天真要做，**验收协议必须是**（否则不可开工）：

1. **H0 侧**：≥40 次独立重复，**H0 命中率 Wilson 95% 上界 ≤ 0.05**；且必须**同时**给出
   「一年内至少一次」的换算值 ≤ 10%。
2. **注入侧**：+10%/+15% 各 ≥20 次，检出率显著高于 H0（Fisher 精确检验 p<0.01）。
3. **真实数据侧**：新增条目的 p 必须 **过 `discover` 的权威 quick-BH 口径**（当前 0.0804），
   不接受「换个窗口就能过」。
4. **语义侧**：`usable` **不得**混层——必须新增独立字段/count（如 `usable_long_window`），
   并在首屏与 `usable_long_term` 分列，禁止相加。
5. **必过反向用例**：断言「H0 数据不得产出任何 usable」（现有测试无此断言，需要新增）。

> 按这 5 条，**N1/N2/N3 全部不达标**（第 1 条就挂：H0 2/8）；
> N1b 也只是「H0 0/8 但 n=8 无法证明 ≤0.05」。⇒ **B（有条件做）的条件目前一个都不满足**，
> 所以结论落在 **C**，而不是 B。

## 6. 真实数据（3515 期）上的即时收益与诚实边界

### 6.1 现状读数（`realdata_baseline.py`，全 124 档）

```
n_tested = 124        best_quick_p_adjusted = 0.0804      verdict = 扫描后无任何维度达到校正显著
现状 usable = 0       现状 persistent = 0
```

最强 12 条候选的长期（全量 3315 期配对差）t 检验：

| 族 | 参数 | 长期 Δ（红球/期） | 长期 p | BH(12) | Bonferroni(124) | 近 6 段 delta 尾 |
|---|---|---:|---:|---:|---:|---|
| **sum_range** | w30, 45–75 | **+0.0542** | **3.74e-4** | 0.0045 | **0.0464** | −0.038, +0.009, +0.022, +0.096, **+0.156**, **+0.109** |
| zone_lag | zone 0 | +0.0474 | 0.0102 | 0.061 | 1.0 | +0.087, +0.040, +0.080, −0.027, +0.120, 0.000 |
| pattern_cont | span, k6 | +0.0355 | 0.0190 | 0.066 | 1.0 | +0.036, +0.122, +0.049, +0.129, +0.009, −0.060 |
| pair | w100, top3 | +0.0333 | 0.0219 | 0.066 | 1.0 | — |
| … 其余 8 条 | | | ≥0.030 | ≥0.069 | 1.0 | |

**真实数据最强候选的长期效应 = +0.0542 红球/期 = +5.0% 相对提升**，而单阶段 MDE = **+26.0%**
——**差 5.2 倍**。这从数据侧再次证明：`persistent` 在 +5.0% 上不显著，不是判据写错，是**物理上检不出**。

### 6.2 新档在真实数据上的产出：**+1 条，而且是假的**

**N1 / N1b / N2 三个方案在真实数据上都会输出同一条**：`sum_range{w:30, lo:45, hi:75}`。

- `p_bonf(m=124) = 0.0464 < 0.05` → 过 N1b；
- 近 3 段 delta = +0.096 / +0.156 / +0.109，全正 → 过 N2；
- **但**：`discover` 的权威口径 `best_quick_p_adjusted = 0.0804 > 0.05` → **R-1 明令不得当「找到了」发布**；
- **且**：`sum_range` 正是 **V12-01 修掉 KeyError 后首次真正运行**的 8 个族之一（此前 0 期数据、0 次检验）。

⇒ **新档的净效果是：把一条「刚解封的维度 + 边界 p 值 + 权威口径未过」的候选，
包装成首屏的「可用」。这是教科书式的假规律，也正是 R-1 要防的那件事。**
**它的期望收益不是 +1，而是 +1 × P(真) ≈ +0.05。**

### 6.3 诚实边界（区分「未检出」与「不存在」）

1. **本文没有证明「不存在任何规律」**。本文证明的是：在 3515 期上，
   用现有 124 档搜索空间 + 现有判据链，`persistent` 的 MDE 是 +26%，
   而用户语境的效应量级 +3%~+15% **在该粒度下不可检验**。这是「未检出」，不是「不存在」。
2. **H0 的 2/8 是小样本点估计**（Wilson 95% = [0.07, 0.55]）。本文**不用**它做点估计论证，
   只用它做**上界论证**（即便最乐观 7% 也不可接受），并配合 §4.2 的年化换算与 §6.2 的真实数据反例。
3. **§3.3(c) 的机制未完全确认**。我做了「冻结集合 vs 动态集合」对照（`h0_selection_diag.py`，
   6 个族 × 20 次），结果**不支持**「资格重选是主因」：动态 vs 冻结的 p<0.05 计数为
   5/120 vs 6/120（≈5%，与名义一致）。**所以本文只声称「实测 H0 率高于名义」，
   不声称「已定位机制」**——这是一个**开放问题**，应在动 L1 之前解决（否则新档的 H0 校准不可信）。
4. **`+30%` 档的逐门衰减仍在跑**（3 次重复），本文该行留空未填；`+15%` 的逐门衰减只有 1 次重复，
   已标注 n=1。凡 n 小的格子，结论只依赖其**方向**（G1=0），不依赖其数值。
5. **本文所有推论只用内存复算，未修改代码**；`discover` 的 `use_cache=False`，
   每次都是完整重扫，因此各次重复相互独立（种子不同）。

## 7. 最终结论：**C —— 不必做**

### 7.1 裁决

> **C. 不必做。** 并且不是「暂缓」（那是 R-4 的原判），而是**在解决 §6.3(3) 的 H0 口径问题之前，
> 任何 L1 新档都不具备可验收性**。
>
> **一个必须写进来的例外（以免本文被读成「一概否定」）**：**N1b（长期显著 + Bonferroni m=124 固定分母）**
> 是唯一在 H0 侧 0/8、且在 +15% 侧 8/8 的变体。它**不是**被数据否掉的方案，而是**证据量不足**的方案
> （H0 只有 0/8，Wilson 上界 0.32）。若 Lead 仍想推进，**唯一可接受的路径是**：先按 §5.1 的 5 条验收协议
> 补足 ≥40 次重复的 H0 校准（约 2 小时机时），再评估——**而不是现在就写代码**。
> 这一步的成本远低于先写 3~4 人日代码再发现误报率不达标。

**决定性理由（按第一指标排序）**：

1. **H0 误报率不可接受**：N1/N2（含 P2 原建议的「长期显著 + 近 K 段同向」）在纯随机数据上
   **2/8 次运行**产出「可用」；年化后 **99.9%** 的用户一年内会看到至少一条假规律。
   现状 `persistent` 是 **0/8、年化 5.3%**。**这是把「基本不会」变成「几乎一定」。**
2. **真实数据的 +1 条是假的**：`sum_range` p_bonf=0.046，但权威 BH=0.0804>0.05，
   且它是 V12-01 刚解封、此前从未检验的族。发布它 = 违反 R-1，且期望收益 ≈ +0.05 条。
3. **打不到问题所在**：瓶颈是「150 期单阶段 × 锁定 α」的 **MDE=+26%**，
   而真实最强效应是 **+5.0%**。任何在"α/窗口选择"上做文章的新档最多把门槛挪到 +18~+25%，
   **仍然差一个数量级**。真正的杠杆是**阶段长度**或**不用阶段**（= quick 层已在做的事），
   这两个都不在 `persistent` 判据里。

### 7.2 现在应该做什么（替代 C 的行动）

| 优先级 | 事项 | 理由 |
|---|---|---|
| **P0** | **把力气放到 L2/L3**（V12 方案的 22.5 人日/21 任务） | L2 是**组合恒等式**，有可验证的真实收益（`P(≥1注≥4红)` 0.019517→0.024504，精确枚举）；不需要统计显著性 |
| **P1** | **把「为什么是 0」讲清楚**（`regime.reason_zh` 已有材料，做 UI 文案） | 现状 0 条是**可信的 0**（H0=0/8、MC=0/6000、MDE 已量化），这比任何假规律都值钱 |
| **P2** | **冻结 L1 搜索的条件化**：按 LEAD_VERDICT §七 的停止条件执行（`min_p_adj>0.05` 且 `max|z|<3.49` → 冻结搜索转 L2/L3） | 当前 `best_adj=0.0804>0.05`，**停止条件已触发** |
| **P3（研究项，不排期）** | 解决 §6.3(3)：为什么动态窗口过滤器的长期 t 检验 p 在 H0 下偏高 | 这是**所有** L1 新档的前置条件；不解决就无法对新档做可信的 H0 校准 |
| **不做** | `persistent_effect` 新档、`ERA_FAMILY_M` 调整、`prereg` 放宽 | 收益 0~0.5pp MDE 或 +1 条假规律，代价是可复现性 / R-1 纪律 / 首屏可信度 |

### 7.3 一句话给用户

> **「persistent 断崖」不是一个需要修的门槛，它是这套系统目前唯一还在正常工作的部分。**
> 它在纯随机数据上一次都没误报过，而它「一条都不给」的原因已经量化：
> 要在 150 期一个阶段上达到锁定显著的 80% 功效，需要 **+26% 的号码偏置**，
> 而真实数据里最强的候选只有 **+5.0%（+0.0542 红球/期）**——**差 5.2 倍**。
> 把它拆掉换成「长期显著」，只会把首屏从「0 条可信的空」变成「每期 ~5% 概率出现一条假规律，
> 一年内几乎必有」。**这不是改进，是把六轮修掉的老毛病装回去。**
> 该做的两件事：**把 L2 的真实组合收益做出来**，以及**把「为什么是 0」讲清楚**。
