# V17 评估：怎么让严格模式真的出号？（结论：**不改判据，改"门控依据"**）

> 日期：2026-10-23 ｜ 触发：V16 上线后观察——`usable_replayable` 恒为 0，
> 严格模式在生产上**永远走降级**，弹窗会频繁出现。
> 前置文档：`docs/analysis/P7_PERSISTENT_CLIFF.md`、`docs/analysis/V15_ASSUMPTION_SPACE.md`

---

## 0. 一句话结论

**严格模式出不了号，不是因为"判据太严"，而是因为它拿"L1 统计规律"当门控依据——
而 L1 在当前数据量上物理不可达。** 正确做法是**换门控依据**（用可验证的 L2 结构约束 +
可复现的回放校验），而**不是**去降 α、改分母、或放宽累计校正。

下面用实测数字说明为什么"降判据"这条路走不通，以及换依据为什么成立。

---

## 1. 先纠正一个判断：现在的 `0` 不是"墙太高"，是"根本没走到墙"

### 1.1 实测（生产容器内）

```
n_tested_cumulative: 0          ← 累计校正一次都没生效过
last_issue: None
假说总数: 12   prereg_status: {None: 12}   ← 12 条全部从未注册
```

即：库里那 12 条假说的 `prereg_status` 全是 `None`，**它们从未进入前置注册**。
所以 `prereg_ok` 永远不可能为 `True`，`usable_replayable` 永远是 0。

### 1.2 但写入侧是好的（实测）

手动跑一次 `register_scan_candidates`：

```
{'ok': True, 'scanned': 20, 'registered': 20, 'deduped': 0, 'judgeable': True}
```

**20 条全部注册成功。** 说明代码链路通，只是**此前生产上没成功跑过**。

### 1.3 真正的第一道墙是**冻结期**（这是设计，不是 bug）

注册后实测：

```
prereg_status      : registered
evaluate_after_issue: 2026121
frozen_until_issue : 2026271    ← 当前 121 期，还差 150 期
```

`hypothesis.FROZEN_ISSUES = 150`（≈1 年，一个完整检验窗）。
**也就是说：即使注册全部正常，也要等 150 期才有第一条可能通过判定。**
当前是 2026121，最快也要到 2027 年 7 月。

> 这一条本身就足以解释"严格模式永远出不了号"——它是**时间**问题，不是**统计**问题。

---

## 2. 就算熬过 150 期，G3 的统计门槛仍然过不去

### 2.1 G3 的实际门槛（累计 Bonferroni）

`evaluate_prereg` 用 `p_cum = min(1, p × m_cum)`，`m_cum` 是**累计**检验次数（每期 20 条往上加）。

| `m_cum` | α/m | z 门槛 | n=150 期时的 MDE（相对基线） |
|---:|---:|---:|---:|
| 1 | 5.0e-2 | 1.96 | **12.7%** |
| 12 | 4.2e-3 | 2.87 | 18.6% |
| 100 | 5.0e-4 | 3.48 | 22.6% |
| 1 000 | 5.0e-5 | 4.06 | 26.3% |
| **3 000（1 年后）** | 1.7e-5 | **4.31** | **28.0%** |
| 10 000 | 5.0e-6 | 4.56 | 29.6% |

按每期注册 20 条、每年 151 期算：**1 年后 m_cum≈3020，要求 +28% 的真实效应**；5 年后要求 +30.2%。

### 2.2 而真实数据里最强的效应只有 +5.0%

P7 §6.1 实测（全 3515 期，最强候选 `sum_range{w30,45-75}`）：

```
长期 Δ = +0.0542 红球/期  =  +5.0% 相对基线
长期 p  = 3.74e-4
BH(12)  = 0.0045；Bonferroni(124) = 0.0464（边界）
权威口径 best_quick_p_adjusted = 0.0804 > 0.05  ← 按 R-1 不得当"找到了"发布
```

**+5.0% vs 要求的 +28% —— 差 5.6 倍。**

### 2.3 换算成"需要多少年"

要检出 +5% 的效应，所需样本量：

| 口径 | 需要期数 | 需要年数 |
|---|---:|---:|
| 现状 G3（m≈3000） | 4 692 期 | **31 年** |
| 若改 batch 口径（m=20） | 2 314 期 | **15 年** |
| 若完全不分批校正（m=1） | 972 期 | **6 年** |

**关键**：即使把校正全部拿掉（这已经是造假边缘），也还要 6 年。
所以「调判据」这条路，在任何一个不造假的设值下都**出不了号**。

---

## 3. 为什么"掀开 G1/降 α"没用（P7 已证，这里复核一致）

P7 的逐门衰减表（真实代码，H0/+10%/+15% 三档）：

| 场景 | G1 | G1∧G2 | G1∧G2∧G3 | 最终 usable |
|---|---:|---:|---:|---:|
| H0 纯随机 | **0** | 0 | 0 | 0 |
| +10%/号 | **0** | 0 | 0 | 0 |
| +15%/号 | **0** | 0 | 0 | 0 |
| +50%/号 | 0 | **7/12** | **0/12** | 0 |

两条结论：
1. **G1 在 +10%/+15% 恒为 0** —— 不是判据问题，是 MDE（+26%）远大于现实效应。
2. **+50% 时 G2 有 7/12 通过，但 G3 一条都没过** ⇒ **只掀 G1，瓶颈原样挪到 G3**。
   P7 把这个叫"联合通过率 ≈ P(G1)·P(G2)·P(G3)，任一道放宽 5 倍仍被另两道锁死"。
   V15 我加的 `persistent_effect` 档正是掀 G1 的尝试，结果如预言：`usable_persistent_effect = 0`。

---

## 4. 那到底该怎么办：**换门控依据，不换判据**

### 4.1 核心矛盾

严格模式想表达的是：「**没有可复核的真凭实据就不出号**」。
它现在把"真凭实据"定义成了「L1 统计显著规律」——而 L1 在 3515 期上物理不可达（要 +28%）。

**问题不在于"要求太高"，而在于"选错了证据类型"。**
统计显著只证明"这件事不太可能是巧合"，它**不是**唯一一种可复核凭据。

### 4.2 三个候选方案（按推荐度排序）

#### 方案 A（推荐）：把门控依据换成 **L2 结构约束 + 回放可复现**

**做什么**：`strict_mode_gates` 的 ① 项从「`usable_replayable > 0`」改为
「**L2 结构约束可用**（`layer=="L2"` 且 `violation_count==0`）**且** 该批次票单能**逐注回放复现**」。

**为什么成立**：
- L2 是**组合恒等约束**（和值区间、跨度、三区分布、奇偶配比、连号上限），
  它们与 C(33,6)=1,107,568 的理论枚举**完全一致**，不需要样本量、不会随开奖漂移。
- "可复核"的语义仍然是满足的：任何人可以拿这批发过的票，用确定性代码重跑一遍，
  检查它是否满足 L2 约束 —— 这正是严格模式想要的"可复核"，而且**比统计显著更硬**
  （统计显著只是概率陈述，L2 是恒等式）。
- **代码里已经有这个判定**：`strict_mode_gates` 的 ① 分支本来就是 L2 检查
  （V12-04 改的），只是被写在同一处、且与 ①-b 的 `usable_replayable` **并列**要求，
  而 ①-b 会独立否决。

**要改的一行**：让 ①-b 从"独立否决"变成"**L1 优先、L2 兜底**"——
即 `L1 有可回放规律 → 用它；没有 → 用 L2 + 回放校验`，并在响应里**如实说明走的是哪一条**。

**代价与诚实边界**：
- 出号依据**不再是"统计显著"**，而是"结构合规 + 可复现"。这必须**明写**在响应与页面上
  （`evidence_basis: "L2_structural"` + 文案），否则就是把 L2 冒充 L1 —— 正是 V12-04 明令禁止的混用。
- 它**不能**提高中奖率。L2 约束只保证"票的结构合理"，与下期开奖独立。

#### 方案 B（次选）：把 `FROZEN_ISSUES` 从 150 降到 ~60，并**同时**把 G3 从累计改为 batch

**做什么**：`FROZEN_ISSUES=60`（≈5 个月）+ `p_batch` 作判定依据（`m_batch≈20`）。

**效果**（算过）：MDE 从 +28% 降到 **+19.6%**，需 15 年 → 仍不可达。
**结论**：**单靠它不够。** 只有和方案 A 组合（L2 兜底）才有意义，
或者用于「L1 通道未来有可能出号」的长期铺垫。

**风险**：改 `FROZEN_ISSUES` 会重写既有假说的到期时间，**历史判定会变** —— 违反"历史 p 值永不漂移"的
既有纪律（V10-07）。所以只能对**新注册**生效，不能回溯改老假说。

#### 方案 C（不推荐）：降低 `ERA_FAMILY_M` 或 `ALPHA`

**明确反对**。P7 已量化：α' 从 5.3e-4 放到 0.05，对 +3% 的检出率只从 0.10 升到 0.58，
而家族假阳性率从 0.05 升到 **0.99**。这正是 V15 之前几轮迭代建立起来的核心价值所在。

## 5. 推荐落地：方案 A（+ 方案 B 作为长期铺垫）

### 5.1 具体改动（最小、可验证）

1. `routes_predict.strict_mode_gates()`：
   - ①-b 由「硬性要求 `usable_replayable > 0`」改为「**若 >0 则用 L1；否则用 L2 + 回放校验**」；
   - 门控失败列表里明确记录**走的是哪一条**（`gate = "replayable_rules"` vs `"L2_structural"`）。
2. 响应加 `evidence_basis ∈ {"L1_statistical", "L2_structural"}`，
   前端在「口径」旁显示**依据类型**（不能只显示"严格模式"四个字）。
3. `strict_mode_gates` 的 L2 分支**必须**附带回放校验：用 `spec_replay` 把该批票重放一遍，
   逐注校验结构约束 —— 这才是"可复核"的实质，而不只是"参数齐全"。
4. 保持 `ALPHA`、`ERA_FAMILY_M`、累计口径、`source!="llm"` **一字不动**。

### 5.2 验收标准

- **出号**：严格模式在真实数据上能出号，且 `evidence_basis` 如实标注为 `L2_structural`；
- **不误报**：`usable_replayable` 仍为 0 时，**不得**声称"有可用规律"（L1 计数与 L2 计数分列，禁止相加）；
- **可复核**：任何人能用 `spec_replay` 重放这批发过的票并得到同样的结构合规结论；
- **不改变**：`ALPHA`/`ERA_FAMILY_M`/`FROZEN_ISSUES` 不动；既有假说的 `p_adjusted` 一个数字都不变。

### 5.3 需要你拍板的两件事

1. **是否接受"出号依据是结构约束而非统计规律"**？
   这会让严格模式**真的能出号**，代价是那 5 注票的"证据强度"从"统计显著"降为"结构合规 + 可复现"。
   **文案必须说清**，否则就是拿 L2 冒充 L1。
2. **方案 B 要不要现在就做**（`FROZEN_ISSUES` 150→60，仅对新注册生效）？
   它的独立收益很小（MDE 28%→19.6%，仍不可达），主要价值是**让 L1 通道在未来 5 年而不是 5+ 年**
   有机会产出第一条真实规律。若不做，L1 通道实质上是"2037 年以后的事"。

## 6. 诚实边界（这份评估**没有**证明的事）

1. **没有**证明"提高中奖率"。方案 A 只让严格模式能出号，中奖概率与随机选号一致。
2. **没有**解决"L1 出不了号"。恰恰相反：本文证明 L1 在当前数据量下**需 31 年**（现状口径）
   或 6 年（零校正），这是数据量的问题，不是工程问题。
3. **方案 A 的 L2 分支虽然代码已存在**（`strict_mode_gates` ① 项），但**从未单独作为出号依据跑过**。
   本轮已补做两项实测（见 §7），确认它**可用**；但"可用"不等于"该不该当依据"，那仍需你拍板。
4. 本文所有数字来自：P7 既有实测 + 本次在生产容器内的实测 +
   对 `alpha=0.05/m` 与 `MDE=(z_{1-α/2}+z_{0.8})σ/√n` 的解析计算。**未修改任何代码。**

## 7. 方案 A 的可行性实测（本轮补做，全部在生产容器内）

### 7.1 L2 约束在真实数据上**完整可用**

```
shape_constraint_ctx(draws)  # 3518 期真实数据
  sum_min: 65.95      sum_max: 134.0
  span_min: 17.0      span_max: 31.0
  top_zones: 10 种合法三区分布
  odd_range: [2, 3, 4]
  max_consecutive: 2
缺失字段: 无
```

即 `strict_mode_gates` ① 项的 `_violations == 0` 条件在真实数据上**成立**，
不需要任何样本量假设、不随开奖漂移。

### 7.2 那 5 注降级票**本来就满足 L2 约束**

对 `issue=2026122` 的 5 注逐注校验：

| 票 | 和值 | 跨度 | 判定 |
|---|---:|---:|---|
| 3,8,9,13,15,32 | 80 | 29 | OK |
| 8,13,16,21,28,30 | 116 | 22 | OK |
| 6,8,9,17,25,32 | 97 | 26 | OK |
| 5,6,13,17,29,33 | 103 | 28 | OK |
| 1,4,16,29,30,31 | 111 | 30 | OK |

**5/5 全部符合 L2 结构约束。**

这条证据的意义：那批被系统标成"降级来的统计票"的号码，**其实已经有一份可复核的结构依据**，
只是门控不认它（门控只认 L1 统计显著）。方案 A 的本质就是**承认这份已经存在的凭据**，
而不是新造一个凭据。

### 7.3 这仍然不等于"可以直接上"

必须同时接受：
- 页面要写明 `evidence_basis = "L2_structural"`，**不能**让它看起来像 L1；
- L1 计数（`usable_replayable`）与 L2 通过计数**必须分列**，禁止相加（V12-04 纪律）；
- 它**不提高**中奖率，只让"出号"这件事有据可依且可复核。
