# V19 重设计：扔掉「AI 挑参数」，改为「AI 做可证伪的假设生成」

> 日期：2026-10-23 ｜ 触发：用户 —「严格模式出号永远不出，还是要想办法改进，扔掉，重新设计基于 ai 的预测方法」
> 前置：`docs/analysis/V17_STRICT_MODE_EVALUATION.md`（L1 需 +28%、真实 +5%）
> 本文**不写代码**，只做诊断与设计。所有数字都是本轮在生产容器内实测。

---

## 0. 结论先行

| 问题 | 结论 |
|---|---|
| 现在的 AI 在做什么？ | **在 124 个人工写死的过滤器里挑参数组合**。`llm_lab.build_user_prompt` 要求 LLM 输出 `filters:[{key,params}]`，key 必须来自维度表 —— 这是**搜索**，不是推理 |
| 它有没有产出增量？ | **没有可证实增量**。历史 45 注匹配样本：LLM 票红球 1.265、统计票 1.182（基线 1.090 红球/期），差异远小于噪声；蓝球 LLM 0.035 vs 统计 0.073，反而更低 |
| ML 通道的「signal_found」可信吗？ | **不可信**。缓存的 `ml_blue: signal_found` 是 `mode=fast, B=20`，`advisory_only=True`——项目自己的判据写着「不得当作结论」 |
| 换成 standard 档后呢？ | B=200 下 p=0.01、trusted=True，**换两个种子都显著**（p=0.01 / 0.005）。但这是**可疑的**，见 §2.3 |
| 真正的问题 | **LLM 被当成了参数搜索引擎**。它的语言推理能力完全没被用上 |
| 重设计方向 | **让 AI 做"可证伪假设生成 + 自动证伪"**，而不是"在既有维度里挑组合" |

## 1. 现状诊断：AI 为什么没起作用

### 1.1 LLM 的职责被限死成"从维度表里挑 key"

`llm_lab.build_user_prompt()` 第 1 轮要求：

```
- ``filters``：1~2 个维度组合（每个含 key 与 params），mode 为 intersection/union
```

`key` 必须存在于 `discovery.FAMILIES`（现在是 32 族 / 134 档）。
于是 LLM 的全部输出空间 = **134 个候选里的排列组合**。

这不是"AI 预测"，这是**让 LLM 当随机搜索器**。而 134 档的搜索空间，
枚举一遍只要 17 秒（实测 `discover(top=12)` 12.8~17s）——**比问 LLM 快 2 个数量级**，
且结果是确定性的、可复现的。用 LLM 做这件事，等于用卡车送一封信。

### 1.2 历史产出没有可证实增量

生产库 `predictions ⨝ eval_results` 实测（45 注匹配）：

| 票型 | 注数 | 平均红球命中 | 平均蓝球命中 |
|---|---:|---:|---:|
| `llm:*` | 34 | 1.265 | 0.035 |
| `stat:*` | 11 | 1.182 | 0.073 |

基线：红球期望 `6×6/33 = 1.091`、蓝球 `1/16 = 0.0625`。

- 红球两者都比基线高 0.1~0.17 —— 这在 34 注上是 1 个标准差内的抖动，**不构成优势**；
- 蓝球 LLM **比统计差一半**，同样在噪声内；
- **样本量 45 注，任何结论都没有统计意义。** 但这恰恰说明：**从来没有建立过"AI 是否有用"的测量**。

### 1.3 项目自己已经怀疑过，并留下了正确的判据

`ml_model.py` 里有一整套「打乱标签对照」置换检验（`diagnose_ml_channel`），
注释写得很清楚：

> 双色球是独立随机事件，一个**正确实现**的概率模型应当学不到任何东西。
> 若真实模型的重要性显著高于打乱标签对照，说明它抓到了真实数据里的某种关联。

这是**正确的科学态度**。问题是：**这套判据只用在 ML 通道上，从没用在 LLM 通道上。**

## 2. 当前那些"信号"到底是什么

### 2.1 缓存的 `ml_blue: signal_found` 是演示档假象

`data/ml_diag_cache.json`（2026-10-17 23:47）实测：

```
mode: fast          → B = 20
p_value: 0.0476     → 恰好 = 1/21，即 n_null=20 时的**最小可达 p**
advisory_only: True
```

项目代码注释原话：

> B=20 时最小 p = 1/21 ≈ 0.0476，刚好卡在 α=0.05 判定线上……
> 任何一点向上偏差都会被放大成高假阳性率（Lead 实测 B=20 时 trusted=True 假阳性率 **35%**）

**所以缓存里那个 `signal_found` 不能作为任何依据。**

### 2.2 standard 档（B=200）下确实"显著"，但这更可疑

我实测（`diagnose_ml_channel(color='blue', mode='standard', max_numbers=3, max_issues=600)`，71 秒）：

| 种子 | p_value | T_mean | 零分布 95 分位 | trusted |
|---|---:|---:|---:|---|
| 0 | 0.010 | 0.002466 | 0.001597 | True |
| 7 | 0.005 | 0.002765 | 0.001555 | True |

**两个种子都显著。** 但注意效应量：`T_mean` 只是零分布 95 分位的 **1.5 倍**。

### 2.3 决定性反证：前向回测里这个"信号"消失了

同一份数据，用最简单的频率法做**严格前向**回测（只用历史、预测下一期蓝球，600 期）：

```
命中 30/600 = 0.0500      基线 1/16 = 0.0625
z = -1.26
```

**命中率低于随机基线。** 若那个置换检验里的"信号"是真可预测性，
前向回测至少不该是负的。

**结论**：`p=0.01` 更可能来自**有限样本下置换检验本身的轻微偏离**
（每个号码只有 600 期、测试集仅 120 行），而不是真实的预测能力。
这也解释了项目为什么在注释里写「非显著不等于信号不存在」——反过来同样成立：
**显著也不等于信号存在**，尤其当效应量只有 1.5×零分布时。

### 2.4 小结：现有一条 AI 通道都没有通过"前向回测"这一关

| 通道 | 自洽判据 | 前向回测 | 判定 |
|---|---|---|---|
| `ml_red` | monitor | 未测 | 无可预测性 |
| `ml_blue` | signal_found（B=200） | **z=-1.26（差于随机）** | 判据与前向回测**矛盾** ⇒ 判据不可单独采信 |
| `llm:*` | 无判据 | 45 注，无统计意义 | 从未被测量过 |

## 3. 重设计：三条原则

### 原则 1：AI 不负责"选号"，负责"提出可证伪的假设"

LLM 的强项不是枚举 134 个参数组合（那是机器的活，而且更快），而是：

- **把用户的语言直觉翻译成可检验的统计假设**（"某几个号更容易出" → 逐号多项检验）；
- **构造新的检验角度**（P2 §2.2 的 `order` 位置独立性，就是这个思路的产物）；
- **对结果做事后归因审查**（判断一个显著是不是搜索出来的假阳性）。

**这一点 V15 已经证明有效**：`order_pos/number_bias/sum_dist` 三族是"换一种提问方式"，
不是"调参数"。虽然它们目前检不出效应（因为数据量不够），但**它们问的是对的问题**。

### 原则 2：任何 AI 产出必须过"前向回测"，不能只过"自洽判据"

现有最大的方法论漏洞：**用置换检验的 p 值当"有信号"的唯一依据**。
§2.3 已经证明这不够——p=0.01 的通道前向回测 z=-1.26。

**新判据（双重门槛）**：
1. 置换检验 p < α（必要）；
2. **前向回测**在独立时段上的命中率优于随机基线，且 z > 1.0（必要）；
3. 两者都过才算 `signal_found`；任一不过 → `monitor`。

这比现在严格，而且**可复现**（前向回测是确定性的，不依赖随机种子）。

### 原则 3：AI 的作用必须可度量、可关闭

现在没人知道 LLM 到底贡献了多少。新设计要：

- 每次出号记录 `evidence_basis`（V18 已做：`L1_statistical` / `L2_structural`）；
- **增加 `ai_pick` 通道的独立战绩统计**：LLM 票与统计票分开记绩效，样本累积到
  n≥200 注时才能下结论；
- 一个开关能整体关掉 AI 出号，且不影响统计通道。

## 4. 具体方案：分三层，每层都有明确产出与判据

### 层 1（马上可做，低风险）：**AI 假设生成器 → 自动证伪**

**做什么**：把 `llm_lab` 的定位从"挑 filters"改成"提假设"，输出**检验规格**而不是"选号集"：

```
LLM 输出（新）：
{
  "hypotheses": [
    {
      "question": "第 1 个开奖位置的号码是否比其它位置更稳定？",   ← 自然语言问题
      "test_spec": {
        "kind": "position_independence",     ← 走 stat_fn 通道（V15 已建）
        "params": {"window": 300, "k": 6}
      },
      "why": "摇奖机出球顺序可能与球道物理特性有关（若无机理请直说巧合）",
      "falsifier": "若前向回测命中率 z<1.0 则判否"
    }
  ]
}
```

**关键**：`test_spec` 只能指向**已实现的检验族**（`FAMILIES` 里的 `stat` 族 + 既有 selector 族）。
不许 LLM 自己发明统计量——那会变成"LLM 编了个看起来像统计的东西"，无法验证。

**产出**：每条假设自动跑 `discover` + `regime` + **前向回测**，三关全过才进候选池。

**收益**：LLM 从"挑 134 档之一"变成"决定问哪个问题、为什么问"——这是它真正擅长的事，
且**结论可验证**（跑不跑得出来是客观的）。

**代价**：LLM 调用变慢（每条假设都要跑回测）。可接受：一天一次，不是热路径。

### 层 2（中等，需要产品决策）：**AI 作为"解释器"，不做选号**

既然选号无增量（§1.2），把 LLM 从出号链路里**摘出来**，改为：

- 对**已经算出来的**统计结果做解释（"这 5 注的结构分布如何，覆盖了什么、漏了什么"）；
- 对**开奖后的结果**做复盘归因（"这期为什么没中/中了，是结构问题还是运气"）；
- 明确标注：**这些文字不参与选号**，只帮助人理解。

**为什么值得做**：现在 LLM 参与出号却无效（还引入 503 风险、延迟、成本）；
改为解释器后，它的价值变成**真实可感的**，而不是"假装在预测"。

### 层 3（长期，明确边界）：**承认并展示"不可预测"**

把「前向回测 z 值」做成首屏可见的指标，每月更新：

```
当前系统前向回测（600 期，蓝球）：命中 5.00% vs 随机 6.25%，z=-1.26
结论：未检出可预测性。系统提供的是结构分析，不是中奖保证。
```

**这不是消极**——它是把"我们试过了，数据说没有"变成可复核的事实，
而不是让用户对着一个"AI 预测"的空壳猜。

## 5. 关于「严格模式永远不出号」的最终处置

V17 的结论仍然是：**L1 需要 +28% 效应，真实 +5%，差 5.6 倍，需 31 年。**
V18 用 L2 兜底让严格模式能出号（已上线）。

**本次重设计不改变这个事实**，但会让"严格模式"的含义更诚实：

| 依据 | 强度 | 当前可得性 |
|---|---|---|
| L1 统计规律 | 最强（统计显著） | **31 年后**（数据量问题） |
| L2 结构约束 | 中等（恒等式，可复核） | **立即可用**（V18 已实现） |
| AI 假设生成 | 待验证 | 层 1 实现后可评估 |

严格模式的语义建议改为：「**有可复核凭据就出号，并明示凭据类型**」——
这已经是 V18 的行为，本次不需要再改。

---

## 6. 我的建议（按优先级）

1. **先做层 1**（AI 假设生成 + 自动证伪）。它风险最低、可验证性最强，
   且能立刻回答"LLM 到底能不能提出有价值的检验角度"。
2. **同时补上"前向回测"这个判据**（§3 原则 2）。这是本次发现的最重要的方法论缺口：
   现有 `signal_found` 没有前向回测支撑，已经在误导人。
3. **层 2 需要你确认**：是否接受"LLM 不再参与选号，改做解释"？这会改变产品叙事
   （从"AI 预测"变成"AI 解读统计结果"），但**更诚实**。
4. **层 3 建议做**，成本很低（一个展示位 + 月度刷新）。

---

## 7. 诚实边界（这份评估**没有**证明的事）

1. **没有**证明 LLM 提假设一定有价值。它的价值需要层 1 落地后用同一套判据测量——
   如果它提的假设也检不出效应，那说明**问题是数据量，不是方法**（这与 P7/P2 一致）。
2. **没有**否定"未来可能出现真规律"。本文只说：**在当前 3518 期上，所有已实现的
   检测手段（统计、ML、LLM）都没有通过前向回测。**
3. **没有**测试 LLM 的"解释质量"。层 2 的价值主张（解释有用）需要单独评估。
4. §2.3 的"前向回测 z=-1.26"只测了**频率法**这一种策略。它不能证明"ML 通道一定无效"，
   但足以证明"置换检验显著 ≠ 可预测"，因此现有判据需要加一道前向回测。
