## 0. 裁决摘要

### 0.1 一句话裁决

**可行，但可行性的全部代价集中在一处：把"扩大定义"从"放宽判据"改成"扩大假设空间 + 保持同一预算"。**
用户要的三段分离在代码里**已经物理存在**（挖掘 `discovery.py` / 验证 `hypothesis.py`+`rule_lifecycle.py` / 使用 `engine.apply_rules_to_candidates`），
本次要做的不是新造架构，而是**补接口契约 + 补一个统一预算**。若只做"扩大定义"而不同时把判据链收敛成单一误差预算，
系统会在 3~6 个月内退化为噪声库——不是因为随机性，而是因为**当前判据链的保守度已经在数学上可量化地错配了 13 倍**（§3.2）。

### 0.2 三条可直接执行的结论

| # | 结论 | 关键数字 / 证据 |
|---|---|---|
| **C1** | **「窄」的根因不是判据，是假设空间的**表达力**；但「一条都找不到」的根因**确实是判据链**，两者必须分开修。 | 现状：29 维度族 / 124 个可枚举组合（`discovery.FAMILIES`、`combo_space_size()=124`）；`order` 字段全仓 0 处读取。判据链在 H0 下 `P(persistent)≈3e-5`（LEAD_VERDICT §2 原因 C）⇒ 124 档的联合 FWER ≈ **0.0037**，即**比名义 0.05 严格 13 倍**。 |
| **C2** | **判据链可以安全放松到 FWER=0.05 并恢复检出能力**：把「五道串行闸门各自扣 α」改成「一条规律一个 e-value，只判一次」。 | 阈值从 z≈4.30 降到 z≈3.538（Bonferroni×124），注入 +10%/号 的实测效应 z=3.69 ⇒ 检出概率由 **0/8** 升到约 **4.5/8**，且 FWER 仍 ≤ 0.05。这是本评审给出的最大单项收益（§3.3）。 |
| **C3** | **「闲时全天候挖掘」在统计上只有一种正确写法：e-process（anytime-valid）**，因为"看得次数"本身就是可选的（optional continuation），固定样本量的任何校正都会被 peeking 摧毁。 | 数值：τ=0.10 的混合 e-process 在 α=0.05 下，对 `cold`+10% 效应（Δ=0.054）**约 2490 期首次穿越**，优于固定 n 的 Bonferroni 功效 0.56（§4.3 表）。 |

### 0.3 对用户立场约束的正面回应（这决定文档怎么写）

用户已知并接受开奖独立随机，并要求**不要再用这一点当论证前提**。本评审完全接受这个约束，并且认为它**不构成任何统计妥协**：

- 统计卫生的定义**不依赖于"数据里有没有真规律"**。它的定义是：**"当数据里没有信号时，系统输出的'可用规律'数量应当受控"**。
  这是一个**关于程序性质（procedure-wise property）**的要求，与世界的性质无关——它对"有真规律的世界"和"纯随机世界"是同一句话。
- 因此本方案的立场可以写成一句用户不会反感、也不自欺的话：
  > **本系统不承诺能找到提高中奖率的规律；本系统承诺：它声称"已验证"的每一条规律，在其自身声明的错误率下都经得起复核，且这个错误率是可见、可审计、不随挖掘次数膨胀的。**
- 娱乐/AI 验证实验的定位下，上述承诺**恰恰是差异化价值**：没有彩票软件能说清"我这 5 条规律凭什么允许出现在首页"。本系统的答案是：**每条规律自带 e-value 与花掉的 α 额度，额度总量封顶。**
- 唯一必须**明确禁止**的表述是"不强调随机性 ⇒ 可以放宽判据"——那等于把 α 从 0.05 改成不设上限，会让 §7 整个剧场复活。**"不强调随机性"约束叙事语气，不约束误差预算。**

## 2. 统一 Rule 抽象：把"扩大定义"变成可插拔注册

> 这是用户第 3 点真正要的东西，也是本评审认为**必须做、且可以低风险做**的部分。
> 目标：新增一类规律 = 写一个 `RuleFamily` 实现 + 注册一行；**不能**新增一类规律时就顺手改判据。

### 2.1 设计原则（三条，缺一即失控）

| # | 原则 | 反例（当前系统里真实存在的） |
|---|---|---|
| **P1** | **规律只能声明"我要被怎么检验"，不能声明"我通过"** | `hypothesis.py:1441` 把 `delta>0` 当"支持"，把负效应判 `rejected`（V12-21 已修，但同类"规律自己决定裁决方向"的写法仍在） |
| **P2** | **所有规律的证据必须汇流到同一个误差预算**，不允许并行存在 6 套 α（§1.1 净结论） | 分段 BH（`ERA_FAMILY_M=32`）× 多尺度名义 α × 累计 Bonferroni 三套并存 |
| **P3** | **每条规律必须可回放**：给定任意历史切片，能确定性重算它的打分器 | `source=="llm"` 规律不可回放 ⇒ `patterns_runtime.py:125` 已经把 LLM 规则永久排除在 usable 外。这个排除是**正确**的，应上升为 Protocol 的硬约束而不是特例判断 |

### 2.2 类型定义（可直接落地，约 200 行，无外部依赖）

```python
# lottery/rule_protocol.py  （建议新增）
from dataclasses import dataclass, field
from typing import Any, Dict, Literal, Optional, Protocol, Sequence

Draw = Dict[str, Any]
Layer = Literal["L1_long", "L1_phase", "L2_shape", "L3_hypothesis", "L4_lifecycle", "L5_ab"]


@dataclass(frozen=True)
class Hypothesis:
    """一条规律 = 假设空间里的一个点（或一个有限参数族）。"""
    family_key: str                                   # 必须 ∈ RuleFamily.KEY，多重检验分组键
    params: Dict[str, Any]                            # 冻结参数：可 JSON 序列化、可哈希
    target: Literal["red", "blue"]
    direction: Literal["positive", "negative", "two-sided"] = "two-sided"

    @property
    def family_size(self) -> int:
        """同族参数组合数 —— 多重检验分母的**唯一**来源。
        禁止在别处再乘一个'预留上限'（如 ERA_FAMILY_M=32）。"""

    def exp_id(self) -> str:
        """sha1(family_key + sorted(params) + target + direction)。
        **绝不含**截止期号/当前期号/运行时窗口（R3 教训）。"""


@dataclass
class Evidence:
    """一次检验的产物：全部是**可观测量**，不含任何裁决。"""
    n_obs: int; effect: float; se: float; z: float
    e_value: Optional[float]                          # 无则 None（旧路径兼容）
    p_two_sided: float
    mde_abs: float                                    # 本检验 80% 功效的最小可检效应（自适应）
    window: Optional[str] = None                      # 'all'/'150'/'era:i'
    extras: Dict[str, Any] = field(default_factory=dict)


@dataclass
class Verdict:
    """**唯一裁决结构**。只能由 §3 的统一预算器产生，RuleFamily 不得自产。"""
    state: Literal["usable", "monitor", "rejected", "underpowered", "invalidated"]
    layer: Layer; reason_zh: str
    alpha_spent: float; alpha_remaining: float        # 可审计
    evidence: Evidence


class RuleFamily(Protocol):
    """一族规律的注册契约。新增规律族 = 实现本 Protocol + REGISTRY 加一行。"""
    KEY: str
    LAYER: Layer                                      # 只能挂一层，禁止跨层求和（V12-04）
    TARGET: Literal["red", "blue"]

    def enumerate_hypotheses(self) -> Sequence[Hypothesis]:
        """① 假设空间：必须有限、无重复、与运行时一致。
        禁止返回'按数据动态决定'的集合（否则分母不可知 ⇒ 多重检验失效）。"""

    def applicable(self, draws: Sequence[Draw]) -> bool:
        """② 适用条件（as-of 严格性）。不可用时应记 underpowered，
        **而不是**静默 continue（V12-01 的 30 档 bug 正是静默跳过）。"""

    def score(self, hyp: Hypothesis, draws: Sequence[Draw],
              window: Optional[str]) -> Evidence:
        """③ 打分器：确定性、只读 as-of 切片。禁止 RNG / 全局态 / 未来信息。"""

    def null_model(self, hyp: Hypothesis, draws: Sequence[Draw]) -> Dict[str, float]:
        """④ 显著性判据：只返回 {'mean','sd'}，**不返回阈值**（P1 原则）。
        必须与 score() 的 effect 同口径（红超几何 / 蓝伯努利 / 形态精确枚举）。"""

    def invalidation_criteria(self) -> Sequence[str]:
        """⑤ 失效判据：返回 ['D1','D2','D3'] 等代码，语义复用
        rule_lifecycle.CRITERION_LABELS(:60)。"""

    def apply(self, hyp: Hypothesis, draws: Sequence[Draw]) -> Optional[Dict[str, Any]]:
        """⑥ 使用方式：返回 {'numbers': set[int], 'weight': float} 或 None。
        协议级硬约束：weight ∈ (0,1]，且只能是候选池内**重排偏置**，
        不得凭空产生号码（沿用 engine.py:622 既有语义）。"""


RULE_FAMILIES: Dict[str, RuleFamily] = {}
def register(fam: RuleFamily) -> RuleFamily:          # 新增规律族只允许改这一行
    assert fam.KEY not in RULE_FAMILIES, f"重复注册: {fam.KEY}"
    RULE_FAMILIES[fam.KEY] = fam
    return fam
```

### 2.3 六个字段为什么必须是这个类型（不能省、不能换）

- **假设空间** `enumerate_hypotheses()`：多重检验分母 `m` 必须**先于看数据**可知。124 这个数目前由 `combo_space_size()` 硬算（对）；但 L2 形态层与 L3 假说库**没有可枚举空间**，分母只能事后累加 ⇒ 这是 §3 要修的核心。
- **适用条件** `applicable()`：V12-01 的 30 档从未运行，根因是"不适用"与"不显著"不可区分（`except Exception`→空集→`sd<=0`→`continue`）。`underpowered` 必须是一等状态。
- **打分器** `score()`（禁 RNG / 禁全局态）：可回放性是"验证"段的全部意义。LLM 规则被 `patterns_runtime.py:125` 排除，**正确原因就是不可回放**——应上升为 Protocol 硬约束而非 `if source=="llm"` 特例。
- **显著性判据** `null_model()` 只返回 `{mean, sd}`，**不返回阈值**：规律只声明 H0，阈值由统一预算器给。当前 `regime.py:101` / `hypothesis.py:116` / multiscale 三处各自硬编码 α=0.05，正是 P2 违反的物理表现。
- **失效判据** `invalidation_criteria()`：必须对齐 `rule_lifecycle.STATES(:50)`/`CRITERION_LABELS(:60)`，否则同一规律会在 L4 被 retired、在 L1 仍 usable。
- **使用方式** `apply()`，`weight ∈ (0,1]`：若允许直接改号，就无法归因 ⇒ §5 全部指标失效。必须约束为"候选池内重排偏置"（沿用 `engine.py:622` 既有语义）。

### 2.4 这套抽象如何让"只要能套上用于预测的都纳入"变成可控

**用户的原始诉求**：「扩大规律定义，只要能套上用于预测的都可以纳入」。这句话在工程上只需要翻译成**两句**：

1. **「只要能套上」= 只要你能实现 `RuleFamily` 的 6 个方法**（其中 `apply` 只允许重排偏置）。
   ⇒ 表达力限制从"必须是选号函数"放宽到"必须是一个可回放的、有限可枚举的、声明了 H0 的打分器"。
   这**已经覆盖** LEAD_VERDICT §1.1 列出的 7 条窄化假设中的 5 条：
   - ① 不再是"选号函数"——`apply` 可以返回任意 `weight` 语义（例：给某注 +0.1 置信度）；
   - ③ 单变量/低维 → 可以多变量（`score` 可读任意历史字段，包括 `order`/`sales`）；
   - ④ 时不变 → 允许 `window` 参数化（多尺度层已具备）；
   - ⑤ 必须覆盖全时间轴 → `applicable()` 允许只在子区间生效；
   - ⑦ 只测红蓝命中数 → `Effect` 的 `effect` 可以是任意可加统计量（和值偏差、跨度、AC…）。
   **剩下 2 条（②集合级可加、⑥"越像随机越被判无效"）是数学约束，不是实现约束**，Protocol 无法也不应该绕过：
   ② 是因为 `z = effect/se` 需要可加统计量才有闭式方差；⑥ 是 `null_model()` 的定义，改它就是 §7 禁止清单第 1 条。

2. **「都纳入」= 纳入的是"注册表"，不是"可用列表"**。这是本文档最重要的一句话：
   > **扩大规律定义 = 扩大"候选池"，不是扩大"可用集"。**
   候选池的大小决定挖掘成本与多重检验分母；可用集的大小由统一预算器决定，且**与候选池大小无关地被 α 封顶**。
   当前系统把这两件事混在一起了（`n_tested` 同时是"分母"和"报告数字"），于是每次扩大定义都在**稀释已有规律的显著性**——
   这正是用户感受到的"加了一堆规律反而一条都不可用了"的统计真相（而非心理作用）。

### 2.5 迁移成本与兼容策略

1. **新增 `rule_protocol.py`**（纯类型 + 注册表，无行为）— 0.5 人日，零风险，不接线。
2. **`DiscoveryFamilyAdapter`** — 0.5 人日，让 124 档立即获得统一身份，`combo_space_size()` 成为唯一分母。
3. **`ShapeRuleAdapter`** — 0.5 人日，必须显式标注 `layer="L2_shape"` 且**永不 usable**（形态层是结构锁不是统计检验，否则它会悄悄绕过 §3 预算）。
4. **`HypothesisAdapter`** — 1 人日，把 `prereg_*` 映射成 `Evidence`；需动唯一写者 `evaluate_prereg`，必须配回归测试。
5. **`engine.apply_rules_to_candidates` 只消费 `Verdict.state=="usable"`** — 0.5 人日，行为等价改造，现有 shadow 测试可兜底。

**总成本 ≈ 3 人日，不需要重写任何现有模块**——这是"第 3 点可行"的主要依据。

### 3.4 重校准方案：一个规律一个 e-value，只判一次

**核心改动（概念级只有一句）**：把「G1、G2、G4、G5 各自扣 α」改为
「**先把同一条规律的所有证据汇成一个 e-value，再用一次性阈值 1/α 判**」。
逐条闸门仍保留，但它们的输出变成 e-value 的**因子**，而不是独立的 α 扣减。

#### (a) 为什么是 e-value 而不是 p 值

e-value 的两条性质正好对应本系统的两个硬需求：

| 需求 | p 值 | e-value |
|---|---|---|
| **多种证据合并**（分段 + 近窗 + A/B 是三个不同检验） | 无通用合并公式（Fisher 需独立、Stouffer 需正态） | **直接相乘**：`E = ∏ E_i`，仍满足 `E[E]≤1`（无需独立） |
| **闲时挖掘 = 反复看**（optional continuation） | 必须预先固定 α 与样本量，否则失效 | **anytime-valid**：Ville 不等式 `P(sup_t E_t ≥ 1/α) ≤ α`，看多少次都不膨胀 |

混叠风险：e-value 只有在 `E[E] ≤ 1`（H0 下）时才有效。**必须用构造性公式，不能拿 `1/p` 硬凑**（`1/p` 在 H0 下期望为 ∞）。

#### (b) 可实现的 e-value 构造（三种，按证据类型分工）

| 证据类型 | 构造 | 公式 | 备注 |
|---|---|---|---|
| **固定 n 的 z 检验**（分段、A/B、方法对比） | 正态混合 e-value | `E = (1+τ²n)^{-1/2} · exp( τ² S² / (2(1+τ²n)) )`，`S = Σ z_i` | 取 `τ=0.10`（见 §4.3 的标定）；**这是 §3 唯一需要新增的数学** |
| **p 值已知的旧路径**（`hypothesis` 现成 p） | 校准器 | `E = κ·p^{κ-1}`，取 `κ=0.5` ⇒ `E = 0.5/√p` | `p=0.05 → E=2.24`；`p=0.001 → E=15.8`。保证 `E[E]≤1` |
| **序贯观察**（近窗滚动、生命周期驻留） | e-process（test martingale） | 同第一行，`t` 为已观察期数 | **这是"闲时挖掘"的正解**，§4 详述 |

#### (c) 合并与判定

$$E_{\text{rule}} = E_{\text{era}} \times E_{\text{recent}} \times E_{\text{AB}} \times E_{\text{calib}},\qquad
\text{usable} \iff E_{\text{rule}} \ge \frac{1}{\alpha_{\text{spent}}} = 20\ (\alpha=0.05)$$

- **交叉验证要求**：合并后若 `E_rule ≥ 20`，必须**至少两个因子各自 ≥ 2**，防止单一超强因子独自抬过门槛
  （这是 `hot`/`cold` 那种"只有一个窗口显著"的情形，要显式排除）。
- `α` 只花一次：`alpha_spent` 落在 `Verdict`（§2.2）里，可由 UI 展示"这条规律花了多少额度"。

#### (d) 预期收益（用 §3.3 的同一张功效表换算）

| 指标 | 现状 | 重校准后 | 依据 |
|---|---|---|---|
| 单检验阈值 z | 4.30（实际） | **3.538** | Bonferroni×124，e-value 阈值 1/α=20 在 τ=0.10 下的等效 z |
| `+10%/号 cold` 单规则检出率 | 0.271 | **0.560** | §3.3 表 |
| 8 次注入重复中预期 usable 次数 | **0/8** | **≈4.5/8** | 0.560×8 |
| 族错误率 | ≈0.0037 | **≤0.05**（不劣化，且回到名义值） | `E[E]≤1` + 124 重 Bonferroni 上限 |
| 达到 80% 功效所需效应 | +6.90% | **+5.88%** | §3.3 表 |

**关键：这不是"放宽判据换检出"。** 错误率从 0.37% 调到 5% 是**回到名义水平**，
把一个过度保守的程序改回它自己声明的水平，是校准（calibration），不是作弊。
**唯一前提是必须同时做 §3.2 的最小修复**，否则 `E_rule` 没有写入路径。

## 4. 多重检验治理：闲时全天候挖掘的正解

### 4.1 问题规模：一天闲时挖掘会产生多少候选

先把数量级算清楚，否则"治理"没有对象。

| 维度 | 数量 | 来源 |
|---|---:|---|
| 维度族 × 参数组合 | **124** | `discovery.combo_space_size()` |
| 多尺度窗口 | **5** | `multiscale.SCALES` |
| 分段（era） | **23**（最多 32） | `regime.py:82 ERA_DEFS` / `ERA_BLOCK=150` |
| 若三层全量交叉 | **124×5×23 = 14 260** | 这就是"闲时全天候"一天能轻松产出的检验数 |
| 加"补集扩展"（V12-21） | **×2 = 28 520** | 补集不增加新信息但增加检验数（`complement_of`） |
| 加 LLM 工坊每轮 `LOTT_LLM_SAMPLES=3` 路生成 | **+3×(每条 ≥1 个检验)** | `llm_lab.py` |

**在 m = 14 260 处**，Bonferroni 阈值 `z = 4.63` ⇒ Δ_crit = 0.0678（**+6.2%**），80% 功效所需 +7.35%。
**即：一天的自由挖掘，会把系统的最小可检效应从 +5.9% 抬到 +7.4%，永久性地（因为累计口径不回落）。**

**这是"扩大定义 + 闲时挖掘"如果不加治理的**精确后果**：用户每扩大一次定义，已有的所有规律就更难被确认一次。
不是比喻——是 `n_tested_cumulative` 只增不减（`hypothesis.py:1936`）的算术结果。**

### 4.2 三层治理架构（职责单一，不可互相代偿）

| 层 | 职责 | 机制 | 产出 |
|---|---|---|---|
| **L-A 注册层**（准入） | 防"看了数据再提假设" | `hypothesis.register_prereg`（已存在）+ 必须携带 `exp_id` / `family_size` / `planned_mde`；配额见 §4.5 | `status="registered"` 的实验 |
| **L-B 判定层**（误差率） | 防"看太多次" | 主层（≤12 族）FWER，α=0.02；探索层 FDR（e-BH, q=0.10），α=0.03；两层相加 = 0.05 封顶 | `Verdict`（usable/monitor/rejected/underpowered） |
| **L-C 报告层**（可审计） | 防"看不懂" | 每条规律必须同时给出 `e_value · alpha_spent · m_family · n_obs · mde_abs`；缺任一字段前端拒绝渲染（V10 B8 教训） | API/UI 字段 |

**为什么三层不能合并**：注册层解决"看了数据再提假设"（选择性偏差），
判定层解决"看太多次"（多重性 + optional continuation），报告层解决"看得懂"（可审计）。
三者失败模式不同，任何一层单独做都会留下一个可被利用的口子。

### 4.3 e-process 标定：具体数值（这是 §4 的核心产出）

**构造**（标准混合超鞅，Howard et al. 2021 的口径，代码约 15 行）：

观测 `X_i` 已标准化为 `z_i`（H0 下 ≈ N(0,1)），`S_t = Σ_{i≤t} z_i`，先验 `θ ~ N(0, τ²)`：

$$M_t = \frac{1}{\sqrt{1+\tau^2 t}}\exp\!\left(\frac{\tau^2 S_t^2}{2(1+\tau^2 t)}\right),
\qquad \mathbb{E}_{H_0}[M_t] \le 1,\qquad
\Pr_{H_0}\!\left(\exists t:\ M_t \ge \tfrac{1}{\alpha}\right) \le \alpha$$

`α=0.05` ⇒ 阈值 `1/α = 20`，`log 20 = 2.996`。

**τ 的选择决定了"对哪个效应量最敏感"**（标定用 §3.3 的实测效应值，`σ=0.8678`）：

| 效应（注入实验实测 Δ） | 效应量 z̄=Δ/σ | τ=0.05 首次穿越期数 | **τ=0.10** | τ=0.20 |
|---|---:|---:|---:|---:|
| `hot` +10%/号（Δ=0.027） | 0.031 | 9 940 | **11 170** | 12 650 |
| **`cold` +10%/号（Δ=0.054）** | 0.062 | 2 400 | **2 490** | 2 800 |
| `cold` +50%/号（Δ=0.135） | 0.156 | 510 | **400** | 390 |
| `cold` +100%/号（Δ=0.270） | 0.311 | 200 | **130** | 100 |

**结论与建议**：
- **取 τ = 0.10 作为默认值**。它在"小效应慢一点、大效应快一点"之间最平衡，
  且对 Δ=0.054 的穿越点 **2 490 期 < 当前 3 516 期** ⇒ 在现有数据量下**可检出**（这是关键可行性判断）。
- `τ=0.05` 对小效应略好但对大效应明显迟钝（510 vs 400），不适合作为唯一取值。
- **不要试图调 τ 去"多检出几条"**——τ 是研究者的先验声明，必须在**看数据前**固定并写入 `config`。
  事后调 τ = §7 禁止清单第 4 条。

**与现行 Bonferroni 的直接对比（同一份数据、同一个 α）**：

| 方法 | 阈值语义 | Δ=0.054 能否在 3516 期检出 | 是否支持无限次重看 |
|---|---|---|---|
| 累计 Bonferroni（现状，m=1240） | z ≥ 4.106 | **不能**（z=3.69） | 不能（每看一次都要重算，m 增大） |
| 固定 n Bonferroni（m=124） | z ≥ 3.538 | **勉强**（power 0.56） | 不能（peeking 破坏 α） |
| **e-process（τ=0.10）** | `M_t ≥ 20` | **能**（t≈2490 穿越） | **能**（Ville 不等式） |

⇒ e-process **同时**更省功效、更抗"闲时反复挖"。这是本文档推荐它而不是"更聪明的 Bonferroni"的全部理由。

### 4.4 现有 `hypothesis.py` 前置注册簿的可复用程度

**结论：可复用约 70%，但必须补 3 个字段、改 1 处语义。** 逐项核对：

| 现有能力 | 位置 | 可复用？ | 说明 |
|---|---|---|---|
| `exp_id` 规范形式（**已剔除期号**，R3） | `spec_exp_id():1717`、`_spec_canonical():1699` | ✅ **完全复用** | V10 的 R3 约束已实现，正是闲时挖掘需要的"同一假设不因重看而变成新实验" |

**最关键的一处语义修改（必须写进规格）**：

> `n_tested_cumulative` 当前是「**判定次数**」的累计——它惩罚的是"你看得勤"，这是错的。

> 把"看得勤"从分母里去掉，正是 e-process 的数学贡献（重看不重罚）。

### 4.5 具体数值建议（可直接写进 config）

| 参数 | 建议值 | 理由（全部可从 §3.3/§4.3 的表反推） |

**关于蓝球的诚实结论（用户最可能不满、但必须写）**：
蓝球 SE = 0.242061/√3516 = **0.004082**。80% 功效所需效应：m=1 时 **+18.3%**（Δp=0.0114）、

建议 UI 上蓝球规律一律标 `exploratory`，不参与 `usable`。

## 5. 评价口径：不以命中率为唯一指标时，用什么判断"规律有用"

### 5.1 五个可计算公式（全部可用现有模块的字段实现）

记第 $t$ 期：命中数 `K_t`、该期规律的期望命中 `e_t`（`discovery.asof_scan` 的 `exp` 字段）、`n` 为有效期数。

**(1) 相对均匀基线的 lift（回答"比瞎选好在哪"）**

$$\widehat{\text{lift}} = \frac{\bar K - \bar e}{\bar e},\qquad
\mathrm{SE}_{\text{lift}} = \frac{\hat\sigma_K}{\sqrt{n}\,\bar e}$$

红球基线 $\bar e = 6k/33$。**示例**：$k=6$、`cold` 注入 +10% 时 $\bar K-\bar e = 0.054$、$\bar e = 1.0909$ ⇒ lift = **+4.95%**。
`lift` 的置信区间必须用 **as-of 配对差**（不是两独立样本），这是 `regime.py` 已经改用配对 t 口径的原因（V8 记录）。

**(2) 选择后偏差修正（回答"这个 lift 是不是挑出来的"）**

从 $m$ 个候选中挑最大者，其偏差的期望近似（winner's curse）：

$$\mathbb{E}\big[\hat\Delta_{\max}\big] - \Delta_{\text{true}} \;\approx\; \mathrm{SE}\cdot\frac{\phi(z^*)}{\Phi(z^*)},\qquad z^*=\Phi^{-1}\!\left(1-\frac{1}{m}\right)$$

| m | $z^*$ | 偏差（以 SE 计） | 在 SE=0.01464 下的绝对偏差 | 占基线 |
|---:|---:|---:|---:|---:|
| 1 | — | 0 | 0 | 0 |
| 12 | 1.63 | 1.63 | 0.0239 | +2.19% |
| 124 | 2.50 | 2.50 | 0.0366 | **+3.36%** |
| 1240 | 3.09 | 3.09 | 0.0452 | +4.15% |

**⇒ 一条"从 124 个候选里挑出来"的规律，其原始 lift 必须先扣掉 +3.36% 才算真实效应。**
当前系统**没有任何地方做这个扣减**——`discovery.discover()` 直接返回 `best_quick_p_adjusted`，
这已经用 BH 处理了 p 值，但**报告给用户的 `delta` 仍是未扣减的选择后值**。这是必须修的显示口径问题。

**(3) Brier 与 Brier Skill Score（回答"概率预测是否比均匀分布更准"）**

33 维红球概率 $p_{tj}$，实际指示 $y_{tj}=\mathbb{1}[j\in R_t]$：

$$\mathrm{BS} = \frac{1}{33n}\sum_{t}\sum_{j=1}^{33}(p_{tj}-y_{tj})^2,\qquad
\mathrm{BS}_0 = \frac{1}{33n}\sum_t\sum_j (p^{\text{unif}}_{tj}-y_{tj})^2,\qquad
\mathrm{BSS} = 1-\frac{\mathrm{BS}}{\mathrm{BS}_0}$$

均匀基线 $p^{\text{unif}}=6/33=0.1818$ ⇒ $\mathrm{BS}_0 = \frac{6}{33}(1-\frac{6}{33}) = \mathbf{0.14876}$。
`engine.py:142` 的注释写"均匀模型约 0.149"，与本推导一致（$\frac{6}{33}\cdot\frac{27}{33}=0.14876$）。
**判据建议**：`BSS > 0` 才算"有信息"；`BSS` 的 95% CI 用 block bootstrap（块长 ≥ 10 期，因为相邻期共享历史特征而有弱相关）。

**(4) 覆盖率（回答"用户实际买到多少"）**

$$\text{coverage} = \frac{|\bigcup_i \text{reds}_i|}{33}\quad(\text{红球}),\qquad
\text{blue\_cover} = \frac{|\bigcup_i \{blue_i\}|}{16}$$

**必须与 `var_ratio` 并列显示**，因为二者方向可能相反（见 (5)）。

**(5) 方差比 var_ratio（回答"票单结构是否真的更稳"）**

沿用 `docs/reviews/R2_STATISTICS_REVIEW.md §3.4.3` 已验证的闭式（全枚举核对到 $10^{-15}$）：

$$\text{var\_ratio} = \frac{\operatorname{Var}[\textstyle\sum_i K_i]}{n\sigma_1^2}
= 1+(n-1)\cdot\frac{11}{27}\left(\bar A-\frac{12}{11}\right),\qquad
\bar A = \frac{\sum_{i<j}|t_i\cap t_j|}{\binom{n}{2}}$$

中性点 $\bar A = 12/11$（不是 0）。三个可断言解析值：$\bar A=0,n=5 \Rightarrow 0.111$；$\bar A=12/11 \Rightarrow 1.000$；$\bar A=6,n=5 \Rightarrow 5.000$。

### 5.2 操作性裁决：什么情况算"规律有用"

**禁止**用单一命中率判定。建议用下面的**四条件合取**（全部可计算、可回放）：

| 条件 | 公式 | 门槛 | 理由 |
|---|---|---|---|
| C-a 效应非零 | `lift` 的配对 95% CI 下界 > 0 | > 0 | 最基础 |
| C-b **扣掉选择偏差后仍非零** | `Δ̂ − SE·φ(z*)/Φ(z*)` 的 CI 下界 > 0 | > 0 | 防 winner's curse（§5.1(2)） |
| C-c 概率层面有信息 | `BSS > 0` 且 block-bootstrap CI 下界 > 0 | > 0 | 防"命中数涨了但概率没变好"（可能是票单结构效应，不是规律效应） |
| C-d 不是单一窗口的偶然 | e-value 合并后**至少两个因子 ≥ 2** | 见 §3.4(c) | 防单窗口过拟合 |

**四条全过 = `usable`；C-a/C-c 过但 C-b/C-d 不过 = `monitor`；任何一条 CI 覆盖 0 = `underpowered`（不是 `rejected`）。**

`underpowered` 必须与 `rejected` 分开，这是 V9 已经确立的口径（`config.py:29` 的 V9 条目："noise 不再是 rejected，改归 monitor"）。
本节把它延伸到 MDE 层面：**当 `Δ_crit > 观测到的 |Δ|` 时，正确输出是"检不出"，不是"不存在"**。

### 5.3 与现有实现的对应关系（避免重复造轮子）

- **已有**：配对效应与 CI（`regime.py` 分段 + 配对 t，V8 已改口径）；Brier 融合（`engine.py:126-183`、`battle.py:110` walk-forward 版）；覆盖率（`engine.ticket_distribution`）；`_HITS_VAR/_HITS_SD`（`rigor.py:72-73`）。
- **需新增**：BSS 及其 block-bootstrap CI（~20 行）；选择偏差扣减（§5.1(2)，~15 行）；e-value（§3.5 M4，~40 行）；`var_ratio` 按 §5.1(5) 闭式暴露。
- **需改口径**：`discovery.discover()` 返回的 `delta` 目前是**未扣减选择偏差**的原始值，直接进 UI 会被读成"真实效应"；应同时返回 `delta_debiased` 并让前端只用后者。

## 7. 禁止清单：会让系统变成"过拟合剧场"的写法

> 用户第 6 点要求不强调随机性。本节的每一条都**不依赖"数据是随机的"这个前提**，
> 而是依赖一个更弱、也更难反驳的命题：**如果一套程序在纯噪声上会稳定产出"可用规律"，那它在有信号时也无法区分信号与噪声。**
> 这不需要用户相信彩票随机，只需要用户相信"程序的行为应当可复现"。

| # | 禁止的写法 | 为什么它是剧场（不依赖随机性论证） | 替代做法 |
|---|---|---|---|
| **F1** | **"只要能套上就纳入 usable"**（把候选池大小当成可用集大小） | 可用集大小若随候选池线性增长，则"每条规律的可信度"必然随新增定义而下降；用户看到的"规律变多了"是分母变大的副产品 | 候选池扩大、**可用集由 α 封顶**（§2.4） |
| **F2** | **事后调整 τ / α / 窗口长度 / 阈值**（"再试一个参数就显著了"） | 这是 optional stopping 的教科书形态：任何固定 α 在无限次调参后必然被击穿（§4.3 已给出 e-process 的正确替代） | 参数在看数据前写入 `config` 并记 `prereg_at`；改动必须新开 `exp_id` |
| **F3** | **用 `1/p` 或 `−log p` 当 e-value** | `1/p` 在 H0 下期望为 ∞，**不是 e-value**，套用 `E≥1/α` 会给出任意大的假阳性率 | 只在 §3.4(b) 的三种构造里选 |
| **F4** | **同一规律按不同截止期/窗口重复注册**（"2026118 截止"和"2026121 截止"算两个实验） | 这会把 5% 放大到 99%（R2_STATISTICS_REVIEW §3.1 的模拟：B=91 时 FWER=0.991） | `exp_id` 规范形式剔除期号（已由 `spec_exp_id` 实现，**必须保持**） |
| **F5** | **"命中率提升"用样本内数据报告** | 阈值来自全样本 ⇒ 样本外必然略好（V6 实测 +0.0308 的纯虚假提升） | 一律 as-of 回放 + holdout（§5.1(2) 的扣减） |
| **F6** | **把 `monitor` / `underpowered` 合并进 `usable` 以"让界面好看"** | 这是 V12-04 修掉的 `usable = long + phase` 跨层求和的同类错误；合并后"可用条数"失去意义 | 三层分列，`all_tiers_sum` 只作为诊断字段（已实现，保持） |

### 7.1 需要向用户明确的一句话（建议直接进 README / 首页脚注）

> 本系统不承诺提高中奖概率。它承诺的是：**首页上每一条"已验证"的规律，都附带它花掉的统计预算（α 额度）与可复算的 e-value；
> 预算总量封顶，且不随挖掘时长增长。** 如果一条规律通过了，你可以复核；如果没通过，系统会明确说"检不出"而不是"不存在"。
