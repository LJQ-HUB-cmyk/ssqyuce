## 0. 监理总结论（一句话）

**四个方向里没有一个能按用户原话字面开工，但也没有一个需要推翻——全部是"改写后可做"。**
真正的开工顺序只有一条路：**先补 Gate 收尾（约 3.5 人日）→ 精简 → 模块化 → 挖/验/用分离 → 闲时挖掘 → LLM 岗位扩展**，任何跳步都会复刻 V10 踩过的坑（§7 对照表）。

## 1. (a) 逐点判定与前置 blocker

### 点 1——模块化：有条件具备

**现状证据**：`api_app.py` 3381 行 79 路由是典型"大泥球"入口；`engine.predict_next`（`engine.py:2279`）被多个通道共用；调度链 `_scheduler_step`（`api_app.py:2146`）里抓取→进化→prereg→快照→生命周期→预测串在一根线上，一步抛异常靠 `try/except print` 保活——**现在靠的是"打印一行字"的隔离**。
**能做到什么**：进程内功能级降级（超时＋熔断＋降级值）＋调度链分段提交＋前端按卡片降级。**做不到什么**：单进程单容器内"一个模块崩了整站无感"（见纠偏 C1）。
Blocker：

- **B1-1 契约冻结**：`resolve_channels()` 唯一判据必须先落地。S2 P0-3 已证明 `source` 三层在现有代码上**无法判定**（`config.py:239/267` 把 json 与设置页写入都回写 `os.environ`，运行时 json 层与 .env 层永久不可区分）——不修，模块开关语义就是糊的。
- **B1-2 测试隔离收尾**：`tests/conftest.py` 已落地（V10-00b），但 S1 P2-2/P2-3 指出 13 处无效 `setenv` 死代码与非路径全局泄漏——模块化拆分必然新增大量跨模块测试，先把地基扫干净。

### 点 2——精简：具备改造条件（唯一可直接开工）

79 个路由就是精简的靶场：`/api/eval/*` 系 10+ 个、`/api/llm/*` 系 8+ 个、mining/replay/regime/lifecycle 各自成套，前端 `app.js` 与之一一对应。**但必须先回答 R4 式问题**：每个端点"有测试/有前端入口/有调度调用/被谁引用"四项证据，否则会删掉点 3 要用的积木（例如 `hypothesis.register/resolve` 看似冷门却是 prereg 的地基）。
Blocker：

- **B2-1 "不能删"清单先冻结**：前置注册簿、备份/迁移链、`/api/health`（含 schema_version）、数据核对、自检——即使冷门也是安全底线，删谁都要 Lead 签字。

### 点 3a——挖/验/用分离：有条件具备

方向正确（这正是 V10 G4/G8 要求的落点），但 S2 证明**写侧是空的**：全仓无 `prereg` 生产者；方案只规定了 `prereg_ok` 的读者（`patterns_runtime.py:110`），没规定谁计算、何时跑；U1–U5 全用 monkeypatch 伪造证物，**实现者可以"永远不产生一条 prereg_ok=True"而全绿**——这是 V10 警告过的"白做"换了个位置重演。
Blocker：

- **B3-1 prereg 写者规格**：`hypothesis.evaluate_prereg(draws, issue, registry_path) -> Dict` 签名＋幂等语义＋调用点二选一写死（`_scheduler_step` 或 `patterns_runtime.refresh`），＋E2E 正例（全程不 mock `lottery/` 内部）＋反向用例（删调用点必须红）。
- **B3-2 接线补洞**：`usable` 三处改法＋`replay_results` 主键改 `(method, mode, issue)`（S2 P1-11：现主键下回放与研究臂互覆盖，两种写语义都会丢数据）。

### 点 3b——闲时自动挖掘：有条件具备

调度器现状是每 1800s 一轮 `_scheduler_loop`（`api_app.py:2387`），开奖日跑全链，非开奖日相对空闲——"闲时"在概念上存在。但**三个硬约束一个都没写**：① 如何判定"系统不进行预测"（在线请求随时来，预测是同步阻塞的）；② CPU/内存配额（容器 768m 上限，宿主 load 已 ~2.0，还有 14 个邻居容器）；③ LLM 配额（远端 API 按 token 计费＋TPM 限流，免费共享池 429/5xx 是常态）。
Blocker：

- **B3-3 资源契约**：闲时判定器（无在线请求 X 分钟＋非开奖窗口）＋三级配额（CPU nice/内存上限/LLM token 预算）＋熔断（在线请求到来 5s 内让路，挖掘任务可断点续跑）。见纠偏 C5。

### 点 3c——扩大规律库（用户原话版）："不具备"

"只要能套上用于预测的都可以纳入"与"验证规律"在逻辑上互斥：纳入标准越松，验证闸门的假阳性负载越重；叠加 3b 的全天候挖掘，候选洪水会把 FWER 推向 1（V10 F5 已算过：91 条拆 91 批 FWER=0.991）。**按原话做，规律库必成噪声库，且 V10-00b 修好的测试隔离会被"字母序巧合全绿"式假绿再次利用。**
改写后（"可插拔注册＋统一闸门"，见纠偏 C2）→ **有条件具备**。
Blocker：

- **B3-4 Rule 抽象＋多重检验治理**：Rule 类型（假设空间/适用条件/打分器/显著性判据/失效判据/使用方式）＋ e-value/在线 FDR/前置注册三选一落地＋"注入偏置必检出＋纯随机不误报"双测试。

### 点 4——大模型：有条件具备

本系统已有生效裁决（`AI_DEMOTION_DESIGN.md`＋`ai_audit.py`）：LLM 从"预测下期开奖"（无标准答案岗）挪到"答案由确定性代码唯一确定"的岗位（解说员＋契约检查），V10 G1/G2/G3 证明"LLM 出号指望显著性验证"是死锁、"给自家候选排序"是猜规则、abstain 三引用是抄写题。**用户"尽可能发挥"的要求与这套裁决不冲突——冲突的是"把 LLM 放回无答案岗位"。**
Blocker：

- **B4-1 岗位矩阵＋金标准**：每一层标 适合/不适合/需改造，金标准必须确定、无网络、无随机；每个适合岗位给输入/输出 schema＋判分器＋降级路径（LLM 挂了系统照常）。
- **B4-2 "不做"清单**：LLM 永不进规律库/候选池（独立 A/B 对照臂，门槛"不劣于基线"）；`demote/upgrade` 不改变状态（AI_DEMOTION_DESIGN §2.3：动作权给 LLM 就是 V10 死锁重演）。

### 点 6——娱乐/验证实验定位：文案层具备，判据层不可谈判

把"不要强调随机性"理解为"UI 不说教、报告不劝退"是合理的；理解为"判据可以放水"则直接复活 V10 F5（分批洗白）与 F7（探针无 rng 却下结论）。**娱乐软件更需要统计卫生**——否则"规律库""AI 验证"两个词都是假的，用户第二周就会发现状态乱跳。见纠偏 C4。
Blocker：

- **B6-1 诚实口径清单**：每处"不说随机性"的 UI 文案，必须配一句可验证的替代陈述（§2 C4 改写文本）。

## 2. (b) 6 处纠偏：原话 → 改写文本

### C1. "系统整个模块化，防止一个崩溃影响系统"

**错在哪**：单节点单容器单进程里，进程崩＝整站挂（health 检查 60s 间隔＋restart 拉起约 2 分钟窗口，期间全站 503）。"零影响"在物理上不存在；V10 R1 早已否决"加容器/sidecar"那条路（本机资源不够）。
**改写**：

> "改造目标为**功能级降级**：任一功能模块（挖掘/验证/出号/AI 网关/通知）超时、抛异常或 LLM 不可用时，同请求其余卡片正常返回，失败卡片显示明确原因；进程级崩溃仍会导致约 2 分钟全站不可用（restart 拉起窗口），由备份＋健康检查覆盖，不在本项承诺内。每个模块上线时必须附带一条'杀死该模块后其余端点仍 200'的测试。"

### C2. "只要能套上用于预测的都可以纳入（扩大规律库）"

**错在哪**：与"验证规律"自相矛盾；无闸门的纳入＝噪声库；且候选洪水下 FWER→1（V10 F5）。
**改写**：

> "任何候选规律都可**注册**（注册≠可用）；纳入规律库展示必须同时通过三道闸：① 前置注册（`prereg_status=passed`，有写者、有到期判定、有 E2E 测试）；② 多重检验校正（累计口径，FWER/FDR 任选其一并写死 α）；③ 失效判据（连续 K 期不达标自动退居 monitor）。注册速率上限 10 条/期，超限需填 `prereg_reason`。**达不到三闸的候选只进'观察区'，永不进出号通道。**"

### C3. "要尽可能发挥大模型在每个位置的作用"

**错在哪**：与可测性/可信度直接冲突。V10 已证明三个"发挥"实为表演：出号（死锁 G1）、自家排序（猜规则 G2）、abstain 引用（抄写题 G3）。"每个位置"包含多个无标准答案岗位，LLM 在那里只能输出不可验证的文本，污染系统可信度。
**改写**：

> "大模型只进入**有机器金标准的岗位**（输入输出 schema 固定、金标准由确定性代码唯一确定、判分误差允许为 0）：解说员、契约检查器、反事实弃权判别、意图→结构化参数、决策解释。**'不做'清单与岗位清单同等重要**：出号候选、衰减动作（demote/upgrade）、显著性判定三处永不交给 LLM；LLM 全挂时系统必须照常出号（纯统计通道），降级路径随岗位一起上线。"

### C4. "不要强调彩票的独立性和随机性、不可预测性"

**错在哪**："不强调"滑向"不检验"，等于授权自欺；且对用户不诚实（负期望是事实：`/api/portfolio/expected-value` 的 expected_roi 为负是部署验证项）。
**改写**（三段式诚实口径，UI 照抄可用）：

> "① 本系统是娱乐软件／AI 验证实验，不承诺任何中奖收益（期望收益为负，见组合期望值卡）。② 我们不拿'随机不可预测'当结论，但拿它当**对照组**：每条规律都要回答'比均匀基线强多少（lift）、强多久（持续期）、什么时候失效（退居条件）'。③ 当前可用规律数为 N（实测 N=0，17 条在观察区）——**先展示 N，再讲故事**。"

### C5. "系统不进行预测时自动利用闲置资源挖掘规律"

**错在哪**："闲置资源"不存在。本机 4 核 load ~2.0，容器内存上限 768m（常驻已用一半），同机 14 个容器（含 1.6GB 的 hindsight-app）；LLM 是远端按量计费＋TPM 限流。无配额的挖掘＝抢在线请求的 CPU/内存＋烧 token＋触发 429。
**改写**：

> "挖掘任务仅在**三条件同时满足**时运行：① 过去 X 分钟无在线预测请求且不在开奖窗口；② 本容器内存水位 < 70% 且宿主 load < 3.0（任一超标立即暂停，断点续跑）；③ 本日 LLM token 预算有余额（挖掘任务走低优先级队列，429 即停）。在线请求到达时 5 秒内让路。**配额数字写进配置项并暴露到 /api/health，超配额运行视为事故。**"

### C6. "对上述 4 点方向进行完善，不对的地方改正"（隐含"四点可并行开工"）

**错在哪**：四点之间是依赖链不是并列项。按 V10 F3 教训（曾把 2 路并行误报为 4 路），`api_app.py` 会被精简、模块化、三段分离三方同时改；`engine.py` 会被模块化与出号改造争 `predict_next`。无序开工＝合并地狱。
**改写**：

> "四点按依赖顺序实施（§4）：Gate 收尾 → 精简（先定不能删清单）→ 模块化（只切精简后的边界）→ 挖/验/用分离 → 闲时挖掘 → LLM 岗位扩展。同一文件同一窗口只属于一个任务；`api_app.py` 与 `engine.py` 的改动必须排号，真实并行度按 2 路排期（§5）。"

## 3. (g) 顺序建议：依赖链与理由

```
Gate收尾(3.5d) → 精简(4.5d) → 模块化(5d) → 挖/验/用分离(7.5d) → 闲时挖掘(3.5d) → LLM扩展(5d) → 总验收(2d)
     │                │              │                  │                  │               │
     └ 已装3/4，差     └ 先划"不能删"  └ 只切精简后      └ 依赖模块边界    └ 依赖验证闸门   └ 消费前面所有
       S1-P0修+契约冻结   再删A/B/C      的边界，接口      （prereg写者）    （无闸门＝噪声）  契约，最后做
```

- **精简必须在模块化之前**：给要删的代码写接口是纯浪费；且精简后的边界才是模块边界。反例：先切后删＝接口大面积作废。
- **分离必须在模块化之后**：prereg 写者的调用点（`_scheduler_step`/refresh）本身就是模块边界，没切分就接线＝线接在泥球上。
- **闲时挖掘必须在分离之后**：无验证闸门的挖掘就是噪声生产机（V10 F5 定量证明）。
- **LLM 必须最后**：每个 LLM 岗位消费前面的契约（快照结构、判分器、降级通道）；且 G1 禁令要求规律库先干净，LLM 才有干净的对照臂可进。
- **Gate 必须最先**：S1 的两个 P0（老库升级零备份；事务内 backup 无限挂起）是"生产库安全网穿洞"级，任何迁移/重构开工前必须补上；契约冻结是后面所有任务的坐标系。

## 8. (f) 最小可行改造 MVT（只能做 3 件）

1. **P0 Gate 收尾（安全底座）**——S1 两个 P0 修＋`resolve_channels()`。理由：这是唯一"不出事"类工作；老库升级零备份＋事务内挂死是穿洞的安全网，不补，后面任何重构都是在无网高空作业。3.5 人日。
2. **P3 的最小闭环（一条真规律走通）**——prereg 写者＋E2E＋`usable` 接线，做到"注册一条、到期判定、快照可用"全程无 mock。理由：它是点 3 的"存在性证明"；没有它，模块化、挖掘、LLM 全是给空转闭环装修门面。约 3.5 人日（P3 子集）。
3. **P1 的 A 批零风险删除（一次真精简）**——无人使用/已被取代/负收益端点＋前端同步。理由：唯一可独立交付用户可见价值（更快、更稳、更少维护面）的工作；且为后续一切拆分缩小战场。约 1.5 人日。

三件合计约 **8.5 人日**，交付物：安全网补上＋一条真闭环＋一个更小的系统。** deliberately 不含**：闲时挖掘（无闸门就是噪声机）、LLM 新岗位（消费前面契约，最后做才对）。
