## 三、设计层面的阻塞问题（不改就不能开工）

### G1　P0-4 第 2 条是**按设计的死锁**（R3，最严重）

方案要求「LLM 候选必须通过前置注册 + as-of 回放且 `experiments.status == passed` 才能进候选池」。
而 `hypothesis.py:1501-1507` 要求"有支持"才升 validated，`patterns_runtime.py:110` 要求 `persistent` 才 usable，`battle.py:81` 明确 `llm` 不可回放 —— **这个集合恒为空**。

> 这就是方案 §1.3 诊断的病（"LLM 结论必然为空 → 闭环空转"），只是**搬了个地方又装了一遍**。

**裁决**：删除该条。LLM 出号走**独立 A/B 对照臂**（逐注配对 `eval_details` + `rigor.strategy_significance`），**永不进规律库/候选池**，门槛降为"不劣于基线"，且允许**长期停在 `eligible`**（在真随机世界里这是唯一诚实的稳态）。

### G2　P0-1 的「决策技能度量」测的不是它想测的东西（R3）

让 LLM 给我们自己生成的候选排序，**正确答案由后端规则（`confidence` / `blue_coverage_plan`）唯一决定** → 测的是"能否猜出我们的规则"，不是"能否预测开奖"。
且样本量不支撑：n=4 时 τ 零假设 sd=0.49，`correct_top1` 在 30 次时 Wilson CI = **[0.095, 0.373]，已含随机基线** → **方案自己定的 N=30 关停判据几乎必然触发**，会把"AI 无用"写成一个从未被正确测量的结论。

**裁决**：删除 P0-1 原设计。改为 R3 给出的 **5 条"可机器 100% 判定"的岗位**（选 2–3 条先做）：
1. **确定性结果的自然语言核对员**（逐字段复算 `eval.aggregate`，允许误差 0）
2. **契约合规检查器**（`filters` 是否落在 `discovery.FAMILY_BY_KEY` 档位内，与金标准一致率 ≥ 99%）
3. **反事实弃权判别器**（注入强信号 / 真随机两类输入 → 算假阴率与假阳率）
4. **用户意图 → 结构化偏好参数**（不产生任何号码）
5. **解释我们自己的决策**（每个数字必须能在 `portfolio_expected_value` 结构体里精确匹配）

> 这 5 条的共同点：**不需要统计功效、30 行样本即可判定、"不做"与"做错"可区分**。这才是"AI 可验证"的正确形态。

### G3　abstain 契约是零信息量的抄写题（R3）

要求 abstain 引用 `n_tested` / `best_quick_p_adjusted` / `expected_false_positives`——而这三项**本来就在 prompt 里**（`llm_lab.py:147-153`），实测 LLM 原文已在复读 91/4.55/1.0。

**裁决**：三项从 prompt 移除，改为要求自算；或改用 G2-3 的反事实弃权假阴/假阳率。**在错误率估计出来之前，UI 不得出现"AI 已核对并声明弃权"。**

### G4　登记簿是否新建第 4 本（R1）

项目已有 3 本：`hypothesis.py:1257 register_hypotheses`（幂等去重 + 累加 attempts）、`:1443 resolve_registry`（状态机）、`patterns.py`（47 条手写规则）。而 `usable` 的**唯一计算点**是 `patterns_runtime.py:104` —— **它目前不读任何注册表**。

> **只新建 `experiments` 表而不改 `usable` 判定 = P0-2 白做：用户看到的仍然是 0 条可用规律。**

**裁决**：二选一——(A) **并入 `hypothesis.py` 加字段**（推荐：无迁移成本，且天然被 `usable` 读到）；(B) 新表 + 同步改 `patterns_runtime.py:104`。方案必须写明选哪个，不能"新表建成即完成"。

### G5　开关体系不能再加第 7 套（R1）

方案新增 `LOTT_PREDICT_CHANNELS`，但"LLM 不出号"用 `LOTT_METHODS=-llm` **早已能做到**（`config.py:155` + `methods.py:6-13` + `engine.py:1576`）。已有 `LOTT_METHODS` / `LOTT_METHOD_MODE` / `LOTT_LLM_ONLY_OUTPUT` / `LOTT_LLM_DISABLED` / `methods_config.json` / `.env` 六层。

**裁决**：删除 `LOTT_PREDICT_CHANNELS`。改为 **V10-00 契约冻结**（约 1 人日）：一份开关收敛方案 + **唯一的 `resolve_channels()` 判据函数** + 优先级链（`methods_config.json > .env > 代码默认`）。同时把 `COVERAGE_OBJECTIVE` 值域变更配上别名表（`expected_value → ev_conserving`）。

### G6　P1-1 选择性推断在本题数据结构上不成立（R2）

- 用 `truncnorm` 近似**有界离散**统计量（K∈0..6），尾部单点相对误差 **26%～98%**（k=1→4% 处 44%～71%）。
- 方案没写清"选择"发生在**单期轴**还是**候选轴** —— 按字面实现必然算错。
- 验收带「3.5%～6.5%」≈ 1 个 MC 噪声宽度，真 α=6.5% 时通过率正好 0.500，且**无 power 项**。

**裁决**：**降级/删除**。改用 **holdout / 交叉拟合**（0.5 人日）：把候选集随机分两半，一半选、一半评。代价小得多，且不需要密度近似。

### G7　CUSUM 在当前数据量下本身不可用（R2）

ARL0=500 的算术没错，但 δ=0.041（=3515 期 MDE）下**中位检出延迟 248 期 ≈ 1.65 年**，90% 分位 642 期；37 个维度同时监控需 ARL0 = 18500 期（≈123 年）。真实残差上实测报警 109 次 vs 纯噪声期望 245 次（0.44×，因非 iid 自相关）→ **iid 标定的 h 在生产上系统性失效**。且与 `regime.py` 的 23 段（`era_block=150`）重复建设。

**裁决**：**砍掉 P1-2**，改为 regime 的 3 处低成本改进。其中 R2 发现一个**现存的静默缺陷**：阶段边界随期数漂移，每加一期所有历史段的 p 值都会变（不可复现）→ 改为**边界锚定化**。

### G8　测试隔离存在真实缺陷，方案的验收命令会把它藏起来（R4）

`tests/conftest.py` **不存在**（git 历史里也从没有过），仍有 **19 处**裸赋值 `config.DB_PATH`。当前 480 全绿**纯属字母序巧合**——R4 用探针复现了 `test_m4_eval.py + test_v10_*` 同会话时 `count_draws() == 0` 直接失败，而单独跑却通过。

> 方案 §3.1 给的验收命令**恰好全是"单独跑单个文件"**，会形成**假绿灯**，直到全量回归才炸。

**裁决**：新增 **V10-00b**（0.5 人日）：建 `tests/conftest.py` 统一 DB 隔离 fixture + 迁移 19 处 + 验收命令一律改为**全量 `pytest -q`**。
