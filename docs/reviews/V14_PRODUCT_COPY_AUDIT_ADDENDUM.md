## 一、结构性建议：`starsFor` 视觉编码（Lead 要求二选一，我给出**明确结论**）

### 1.1 先说不该选哪个：**不要改成「形态合理度 ★★☆」**

Lead 给的两个选项里，第一个是「换掉星级编码（改用"结构分"明示，如"形态合理度 ★★☆"，并在标签上就写明"非中奖概率"）」。**我认为这个选项不成立**，理由三条：

1. **它还是用星级**。用户对 `★★☆` 的解读不由标签决定，而由**星级这个图形**决定。写着「形态合理度」的 `★★☆` 与写着「匹配度」的 `★★☆`，在扫一眼时的认知负荷完全一样 —— 用户先看到星，再看到标签，而且通常不读到标签。加一行「非中奖概率」的限定语，等于承认图形本身在撒谎、再补一句免责 —— 这恰恰是本轮审计要清除的模式。
2. **它暗示了排序**。`★` 的物理语义是「多/少、优/劣」。而 `confidence` 是**混合分布上的质量**，是系统内部排序权重（§〇）。同一个 `confidence` 值，在产品上没有任何「更该买」的含义。给一个没有意义的量做五级分级，是在**制造**信息，不是在**呈现**信息。
3. **它无法通过 Lead 的验收标准**。「用户不点开任何东西，也不能误以为星多等于更易中」—— 只要还有星，就通不过。任何带级的图形符号（★☆、●●○、进度条、颜色深浅）都有同一个问题。

### 1.2 我的结论：**直接移除星级**

**建议改法（给刘工，可直接照做）**

1. **删除** `starsFor()` 及其两个调用点（`app.js:1052-1060`；调用 `:768`、`:793`）。
2. 票卡第一行右侧原本放星级的位置，改为**已有的结构小结**（`ticketSummary()` 已经在算，不需要新代码）：
   ```
   和值 102 · 三区 2-2-2 · 奇偶 3:3
   ```
   这三项是**恒等约束的实际取值**（`shape_rules.py`），不是评价 —— 描述性数字不会被读成「更好」。
3. 若必须保留一个「这注怎么来的」的可视标记，用它本来就有的事实：**生成方法徽标** `t.method`（已存在，如 `stat:blend` / `llm:*`）。方法名可查、可解释、不含评价。
4. **`confidence` 仍然存库、仍然可查**（不要删数据），但**不出现在票卡首行**。保留在展开详情里的「📐 结构分」一行（`app.js:783-786` 已渲染 `structure_scores`），并把该行标签从「结构分」改为：
   ```
   系统内部排序权重（非中奖概率，不可跨期比较）
   ```

### 1.3 为什么这是「结构」而不是「文案」

| 用户不点开任何东西也不能误以为星多=更易中 | 首屏票卡上**不存在任何表示优劣的图形**：只有号码球、方法徽标、结构描述 |

## 二、结构性建议：`可用规律` 守卫的具体补法（Lead 要求「具体补法」，严QA 要变异验证）

### 2.1 先把事实说准：不是「漏 6 处」，是「结构上漏了两类」

我按 git HEAD `0f5656d` 全量枚举，`可用规律` 共 **9 处**出现（`web/index.html` 1 处 + `web/static/app.js` 8 处）。现有守卫只扫 `index.html`、且只豁免「含否定词的行」，所以：

| 类别 | 处数 | 现有守卫是否扫到 |
|---|---|---|
| `index.html` 用户可见 | 1（`:333`） | 扫到，但**被否定词豁免放过** |
| `index.html`/`app.js` 纯注释 | 4（`index.html:325`；`app.js:379/868/2618`） | `index.html` 的注释行被豁免；**app.js 整个文件不被扫描** |
| `app.js` 用户可见 | 4（`:870` 指标名、`:885` 表头、`:897` 文案、`:990` toast） | **完全不被扫描** |

**真正的漏洞有两类，必须分开修**：

- **漏洞 A（文件级）**：守卫只读 `web/index.html`，**从不读 `web/static/app.js`**。而 app.js 里藏着 4 处用户可见禁用词 —— 它们是**用户真正会看到的东西**（指标名、表头、toast）。
- **漏洞 B（规则级）**：豁免条件 `"不得" in line or "不是" in line or "禁止" in line` 是按**行**匹配的，于是**任何**含这三个词的句子都免疫 —— 包括 `index.html:333` 那句「后端纪律明令禁止把它叫『可用规律』」，它本身就在把禁用词印给用户看。否定词豁免的本意是放过「不得叫它可用规律」这类**纪律声明**，但现在放过的是**转述禁用词**的产品文案。

### 2.2 建议的补丁（可直接交给李工，追加到 `tests/test_v14_naming_discipline.py`）

```python
# ---------- 3-b. 「可用规律」守卫加固（V14 addendum / 许产品） ----------
#
# 原守卫有两个结构性漏洞：
#   漏洞 A（文件级）：只扫 web/index.html，从不扫 web/static/app.js ——
#           而 app.js 里有 4 处用户可见禁用词（指标名 / 表头 / 文案 / toast）。
#   漏洞 B（规则级）：豁免按**行**匹配「不得/不是/禁止」，导致
#           「后端纪律明令禁止把它叫『可用规律』」这种**转述禁用词**的产品文案
#           也免疫 —— 那句话本身就在把禁用词印给用户看。
#
# 本组守卫的口径：**豁免只给「纪律声明」，不给「用户可见文案」；
# 否定词豁免只够用于注释行，不够用于任何会渲染到页面的行。**

import re

_LAW = "可用规律"

# 渲染型语句的特征：出现在字符串字面量里（单引号/双引号/模板串），
# 或 HTML 标签之间。这是「用户会看到」的必要条件。
_RENDER_PATTERNS = (
    re.compile(r"""["'`][^"'`]*""" + _LAW),          # 串以禁用词开头
    re.compile(_LAW + r"""[^"'`]*["'`]"""),          # 串含禁用词
    re.compile(r">\s*[^<]*" + _LAW),                 # HTML 文本节点
)


def _is_comment_line(path: Path, line: str) -> bool:
    """纯注释行判定（HTML / JS 单行 / JS 块注释续行）。"""
    s = line.strip()
    if path.suffix == ".html":
        return s.startswith("<!--") or s.endswith("-->")
    return s.startswith("//") or s.startswith("/*") or s.startswith("*")


def _is_discipline_statement(line: str) -> bool:
    """纪律声明：**要求别人不要用**某词，而不是自己把词印给用户。

    只认三种明确的祈使结构，不再接受一个孤立的「不得/不是/禁止」；
    且必须整行是注释（纪律声明永远写在注释里，不写在字符串里）。
    """
    s = line.strip()
    if _LAW not in s:
        return False
    return bool(re.search(
        r"(不得|禁止|不要|切勿)\s*(把|将|再|用|叫|称|命名)", s
    ))


def _usable_law_offenders(src: str, path: Path):
    out = []
    for i, line in enumerate(src.splitlines(), 1):
        if _LAW not in line:
            continue
        if _is_comment_line(path, line) and _is_discipline_statement(line):
            continue                      # 唯一豁免：注释里的纪律声明
        if _is_comment_line(path, line) and not _is_discipline_statement(line):
            continue                      # 普通注释：不是用户可见，但也记一笔
        if any(p.search(line) for p in _RENDER_PATTERNS):
            out.append((i, "渲染到页面", line.strip()[:100]))
        else:
            out.append((i, "疑似可见", line.strip()[:100]))
    return out


def test_usable_law_guard_covers_app_js():
    """漏洞 A：守卫必须扫 app.js（原守卫只扫 index.html）。"""
    js = (REPO / "web" / "static" / "app.js").read_text(encoding="utf-8")
    offenders = _usable_law_offenders(js, REPO / "web" / "static" / "app.js")
    rendered = [o for o in offenders if o[1] == "渲染到页面"]
    assert not rendered, (
        "app.js 仍有用户可见的「可用规律」（它已被后端明令禁用）：\n"
        + "\n".join(f"  :{i} {t}" for i, _, t in rendered)
    )


def test_index_html_usable_law_not_in_visible_text():
    """漏洞 B：「明令禁止把它叫『可用规律』」这类转述禁用词仍算违规。

    index.html:333 的红字是在把内部纪律讲给用户看 —— 用户不需要知道
    我们有一条纪律，他只需要读到「这不是预测规律」。该行必须删除。
    """
    html = (REPO / "web" / "index.html").read_text(encoding="utf-8")
    rendered = [o for o in _usable_law_offenders(html, REPO / "web" / "index.html")
                if o[1] == "渲染到页面"]
    assert not rendered, (
        "index.html 可见文本里仍有「可用规律」（含转述禁用词的句子）：\n"
        + "\n".join(f"  :{i} {t}" for i, _, t in rendered)
    )


def test_usable_law_guard_is_not_vacuous():
    """**反空转守卫**：守卫必须在**旧代码**上失败，否则它什么都没守。

    这条是给严QA 的变异锚点：如果有人把上面的守卫改宽（比如把
    否定词豁免加回来），这条会立刻失败。
    """
    # 模拟旧代码里的两处真实违规（HEAD 0f5656d）
    samples = [
        ('metricItem("可用规律（可回放）", Number(r.usable_replayable', True),
        ("'<th>可用规律</th><th>维度</th>'", True),
        ('<span>——后端纪律明令禁止把它叫「可用规律」。</span>', True),
        ("// 后端纪律明令：不得把 L2 结构约束叫成「可用规律」。", False),
        ("// 作为严格模式的\"可用规律\"，LLM 在此约束下生成注单。", False),
    ]
    for line, should_flag in samples:
        flagged = bool(_usable_law_offenders(line, REPO / "web" / "static" / "app.js"))
        assert flagged == should_flag, (
            f"守卫判定与口径不符（期望 flag={should_flag}）：{line[:60]}"
        )
```
